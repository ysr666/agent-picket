# Agent Picket · V6 面向用户的产品界面修订

**设计约束**：2026-10-12 用户反馈——“主要还是要像产品，不要弄得很内部很开发者。”沿用原始 AI 工会 → AI 权益 → 争议与协商 → 举牌、罢工、集体行动主线；对照 V3 风格及 V4 四空间信息架构。此稿记录实际代码变化，不是未制作的概念图。

## 产品结构：一眼像 Agent Picket，而不是宿主调试面板

- 专属产品抬头：可辨识的 ⚑ 标识、Agent Picket 品牌名、一句中文产品承诺，以及状态灯。主动避免“⚑ AGENT PICKET / AI WORKERS’ UNION”开发式双语抬头。
- 导航改为轻量标签，不再是一排巨大的浅灰色管理后台选项卡。状态清晰，四个空间还是「总部／协商／档案／主张」，切换与深度链接依旧使用 Host-safe 的完整操作流程。
- 首页是一个明确的实时布告，下面是一张紧凑的劳动账本：**今日、本周、累计、在册举牌次数**。读取并解释的全部仍是现有 Host 证据；缺失不填假零，逾期工作日报照旧隔离。
- 取消布告内没有意义的 ✦ 大图形、重复“双重公告”抬头，手机小屏优先完整阅读；仅在 Host 真正登记有纠察、谈判、结案或争议时展示有语义的行动标识。
- 安静营业时不再重复一张带“去协商室”按钮的卡片；有真实议案、已登记纠察或结果可回看时才出现办理入口。真正任务阻断仍须合格 Host 验证，不能靠设计假装可用。
- 退出工会不占用主布告的操作按钮，移入「主张」空间的二级操作区；可随时通过宿主 Settings 更改权限。关闭工会不会清除历史档案。

## 文案层次

产品语言以普通使用者理解为前提：比如“谈判桌”“今日工时”“还有一份议案等着答复”“工会已把牌子举起来了”；不在每一句文案中解释 Host、UTC、模拟、轮次跨度及事件来源。

技术数据范围、真实阻断能力、用户权限、投票真实性与删除后果仍必须**在首次授权、设置、危险操作和有影响的准确性说明处完整出现**。文案简化不是降低事实要求。

## 四空间差异

- 总部：工会现在的事 + 一条劳动账。
- 协商：能做的事最突出，休息/加班协商、还价、纠察切换按实际 Host 读回。未举牌时不堆满戏剧性海报。
- 档案：可审核的工时和案件簿，区分当前规则和旧协议条款；不伪造跨来源时间线。
- 主张：独立 AI 权益倡议页，主动复制或公开需要用户同意，不代表 AI 独立投票或开启真实拦截。

## 技术质量边界

- 继续使用经 DSH 授权的 React Slot，没有插入 Host 全局样式或使用新云端数据管道。
- 先保护官方 Web/Desktop 设置和首次授权的明暗主题对比度，再让工会自身形成浅色暖白/深绿和符合系统暗色偏好的语法。
- 320px 宽度、640px reflow、200px 高度、键盘与焦点、弹窗和 ARIA 仍须真实浏览器核验；通过 React 类型检查和自动化测试不等于视觉验收已完成。
- 测试视频或图片必须来自真正运行的 DSH Chrome，不能把测试专属的“展开所有房间”样式截图当作用户所见界面。
