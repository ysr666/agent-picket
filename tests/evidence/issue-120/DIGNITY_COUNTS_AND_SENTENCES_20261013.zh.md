# Agent Picket · 沟通与尊严：次数和原句（#120 增量）

日期：2026-10-13。

## 为什么上首页

工会不能只讲工作量，还要有证据地关心对待 Agent 的方式。原本 #79/#83 检测、尊严委员会、真实浏览器同会话回读都已存在，但规则命中次数埋在很深的协商室里。

本轮交付：
- 「总部」工时账本下方一条紧凑的**沟通与尊严**：**疑似辱骂命中次数 / 待复核次数**，外加「查看记录」操作。
- 数字仅来自本次、已授权的真实 Host `/api/agent-picket/dignity/v1` 只读快照；授权 OFF 时不可见；不可用/加载时显示「—」，已观测真实零显示 0，绝不伪造永久累计。
- 「查看记录」进入有真实 Host 记录的尊严委员会；保留原有主动申诉、规则异议、经人点击的象征性举牌、可撤回案件等逻辑。
- 对展示的任何规则命中都不使用「已证实辱骂」字样；正确语义是**疑似辱骂线索**。Host 人源仅标注 claimed，不能把引用/教学/代码/日志里的匹配当真人辱骂。
- 中英双语，手机 320px 可换行、宿主深色主题及 forced-colors 有可用文本对比与按钮焦点。

## 为什么这轮不能显示“被辱骂的句子”

当前官方授权接口明确**只提供 `checked/safe/review/targeted/latest` 和来源/生命周期标签**；Browser 会话仅读可验证的聚合数；Host 内存检测也刻意不保存原句。前端**没有**真实命中原文可显示。

因此本次只在委员会写明「原句暂未提供；请回原对话核对上下文」。不会把测试语料、模型想象的句子、其他会话原文或保密消息伪装为真实证据。即使用户请求查看，也不能通过搜 DSH 私有日志、未经授权 HTTP 端口或自己抓取聊天 DOM 绕过现有隐私策略。

## 真正完成“逐条原句查看”所需独立工程

建议按 #79 / #83 的严格前提建设 **仅用户主动触发的受限原文查阅**，先由官方 Host 公布有鉴权、保证同一会话来源的快照/回调。必须包括：

1. 明确用户操作「本次临时查看命中句子」，默认关闭。当前会话独立授权，不擅自持续存储；会话更换、关闭工会、退出面板后清空读取到的临时原文。
2. 只允许 **真实原始用户消息**，排除引用、教学案例、代码/日志、工具结果、模型输出；必须显示必要上下文，不仅截取会导致断章取义的片段。
3. 严格限制事件数和文本字数，不返回 Session 身份、附件、凭证，不扩散到统计报表、导出、GitHub、模型外部服务或插件遥测。校验官方 Host 权限、User Scope、响应长度、时效与撤销竞态。
4. 每一条展示为「待复核的原句」，附「可能误判」和用户主动的异议/申诉操作，允许纠正；不因规则匹配直接封禁或实施真实阻断。
5. 通过跨标签、重启、权限撤销、请求取消、含敏感字段/超长文本、脚本注入和用户真正关闭页面测试。若 Host 无法保证安全，不提供该按钮。

这个新读取能力**不是当前 V1 合同的一部分**。没有 Host 和真人验收证据前，不能在 PR 或 UI 里称已交付“原句列表”。

## 测试

`tests/dsh-native-rights-ui.test.ts` 验证 Host 计数、0 与 — 区分、授权关闭隐藏、没有泄漏或伪造原句。可选 `PICKET_DIGNITY_E2E=1` 在隔离 DSH 0.2.0-rc.2 中用实际用户来源的人工测试短句触发内存计数，并验证宿主截图的首页数字与官方 API 读回一致。生产中不会使用测试短句或泄露用户原始消息。
