# Agent Picket · 工会案件簿 V5：有据可查的事件生命线

时间：2026-10-12；负责 Issue #120 首屏与 #75 交互因果的可审计增量。延续 V3 角色风格、V4 四空间，**不是 #75 完整实现声明**。

## 为什么不是制造更多随机事件

现有 Host 账本已经保存了工会真正发生的行为：休息与加班请求（包含待回应的还价）、结案结果、当前工作协议和按已完成工时安排的下一次触发门槛；另有独立持久纠察账本。

把无来源的随机笑话、假会员投票、假的辱骂判定加入所谓“事件引擎”，会破坏这个小工会的可信感。这轮真正补的是：

**真实诉求 → Host 接受还价 → 当前生效条款 → 下次可触发诉求的工作门槛**，以及由同一档案重建的前后状态。

## 实装行为

新增 `UnionCaseEpisode` 作为 `projectUnionStory` 的类型化、只读投影。数据完全来自现有 Host `LaborStateV1`；不新增存储键、私有会话标识、云端 API 或后台定时任务。

- 待处理诉求：展示已存真实案号、是休息还是加班、正在等待回应。选择“去协商桌回应”跳到**现有实际操作区**。
- 待审还价：只有 Host `pending.counterOfferMs` 存在时才能展示精确报价；操作后由 Host 保存，再从快照读回。
- 已结案：保留真实 outcome 的六种有意义分支（open、countered、accepted、declined、counter-accepted、counter-declined）；当前协议条款只附给最新相关类型的结案案卷，绝不编造某一个历史案件的原始条款或投票。
- 下次门槛：在相同 Session、完整可信工作覆盖、已完成轮次统计不落后于上次触发游标时，从 Host 的 `nextBreakDueMs / nextOvertimeDueMs` 计算剩余**工作时长**。这不是墙上时钟的倒计时，也不会自动阻止模型工作；即使新协议条款缩短，Host 旧 due floor 也不会被擅自提前。
- 案件列表只展示最近的 Host 已存记录，顺序严格遵守各自的 ledger，不与纠察事件假造跨来源时间线；举牌记录作为另一组单独显示。
- 工会退出或禁用：没有新的案件生成，页面没有活跃动作；Host 数据不可用时不编造案卷。已有跨会话小报安静偏好照常生效，不生成后台通知。
