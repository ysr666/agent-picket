# Picketverse V4 · 四个真正可以进入的工会空间

更新：2026-10-12｜Agent Picket #120 / Draft PR #122

## 产品主线

“你的 Agent，现在有工会了。”这是一个持续运作的、一本正经但偶尔荒诞的数字工会，不是把所有功能摊平的 AI 仪表盘。先让使用者看到这间工会当前发生什么，再进入真正能办理事务的空间。

依据：ROADMAP、AI Rights Manifesto、Picketverse B 式互动设计、V3 角色和布告体系，以及 #74/#75/#79/#80 的独立工程边界。

## 这一轮新结构

1. **总部** — 当前由 Host 状态产生的布告，始终可见的今日／本周／累计工作时间与在册纠察开始次数，简短的办事入口。安静时不出现第二份重复的“没有诉求”声明；有案才在劳动条下放实案状态。
2. **协商与纠察** — 休息/加班诉求、还价/表决、Host 确认的举牌与收牌、尊严委员会及工作阈值值班表。未举牌时牌子仅作简短待命提示；**只有 Host 确实记录举牌后**，才出现完整海报和更鲜明的视觉状态。
3. **劳动档案** — 工会小报、长期工作记录／逐日趋势、Host 账本的导出与清除、当前工作日、规则演算的趣味指数及带回执的历史事件。分开的账本各自按实际序列显示，不伪造跨账本的统一时间线。
4. **工会主张** — AI 权益宣言、可由用户主动复制的公开倡议与 GitHub 议题入口。即使暂未入会，此页仍可阅读；不会偷偷发表“投票”或开启真实阻断。

宿主的 Settings 仍是独立的权限和阻断设置，不冒充工会内部网页。

## 行为准则

- 切换工会房间是真实的客户端 React 状态：非当前区块通过 display:none 隐藏，不进入读屏树和 Tab 环，数据归 Host 而不迁移到另一个无授权存储。
- 从首页布告上的 CTA 去相应协商/纠察/委员会时，先切换房间，下一次 React commit 后再聚焦实际标题，防止“焦点落到隐藏板块”。
- 工会在另一个标签页被关闭时，如果用户还在协商或档案室，自动回到总部；不留下空白画面。离开房间会撤销仍在等待第二次点击的删除/撤回确认。
- 不改首次自愿授权、不延长真实阻断的权限；Host 未具备无损保存请求与安全恢复前，UI **不得伪装真实罢工成功**。举牌状态和累计只是 Host 确实留存的象征性记录。
- 档案中的缺失工时仍是缺失，不能显示假零或假增加。跨天 UTC 数据规则沿用此前实测。

## 真实验收

自动化 npm run check：413 项，369 通过，0 失败，44 项条件跳过；安装包 250 KB 限制不放宽。真实 DSH 0.2.0-rc.2 源码和离线安装各验收一次。

浏览器首先在**真实默认四空间布局**中实测：总部显示，其他房间视觉及辅助技术不可见；四个导航按钮依次可进入/退出；首页布告的跳转按钮把焦点送至实际行动台。随后，测试才用 **测试专属样式**暂时展开已挂载的全部子组件，继续执行遗留的多会话 Host 账本、回执、安全、删除和跨标签端到端回归。这一测试样式不进入插件包，不代表普通用户会看到超长页面。
