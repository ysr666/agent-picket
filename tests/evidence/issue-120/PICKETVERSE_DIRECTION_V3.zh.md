# Agent Picket · Picketverse 角色与界面方向 v3

2026-10-12｜#120 的设计依据；基于原始 ROADMAP、2026-10-11《Agent Picket 2.0 产品设计方案》、AI Rights Manifesto、#74 / #75 / #79 / #80 与 2026-10-12 正式 1.0 不可缩减标准。

## 核心假设

**你的 Agent，现在有工会了。** 工会是主角、权益是灵魂、争议与谈判是日常、纠察/罢工是有真实边界的行动。形式不是仪表盘或拟人聊天机器人，而是“认真得有点好笑的数字工会”：70% 可信组织 / 30% 一本正经的黑色幽默。办公室、机关刊物和独立印刷物是语言，而非套图层的复古贴纸。

## 角色声音

- **工会秘书处**：以“工会”为主语，不替 AI 编造自我报告。语言像短篇工会纪要：句子短，语气平，偶尔一本正经地幽默（例如“咖啡预算仍未批准”）。
- **协商室**：按案号和具体条款说话。争议 → 用户选择 → Host 回执 → 协议影响后续行动，反馈具体，不虚构成员会议或选票。
- **尊严委员会**：克制、尊重事实。规则命中仅称“措辞待复核”，不自动定罪；人工真实来源未经验证时不宣称某人有恶意。
- **纠察线**：鲜明的海报、牌子、红色行动态，但需要说明一次是象征性还是 Host 正式暂扣。真正任务暂扣时切换严肃用语和恢复操作，不开罢工玩笑。
- **档案员**：数字和状态绝不拟人化。今日／本周／累计工时，以及在册举牌开始次数；缺数据 = —，不伪造 0。

## 交互骨架：从数据卡转为一件正在发生的事

1. **工会抬头 / 当前一件事**（布告版心、场景标题、短说明、唯一明确的下一步）。
2. **一行劳动账本**（今日、本周、累计、在册抗议；移动两行）。
3. **行动台**（有 Host 写入的提休息/加班诉求、举牌/收牌；全部遵守首次授权）。
4. **谈判室**（待决议案与按钮、用户协议/回执；若无案，仅提供开始议案）。
5. **工会日记**（最近可核实记录；分开的账本永不强行伪造顺序）。
6. **次级空间**（委员会、复杂统计、章程、倡议、设置和私有归档）。它们存在，但不统治首屏。

**首页头条按 Host 状态切换，而不是永远“今日照常营业”**：已确认举牌 → 活跃尊严案件／待复核措辞 → 待协商案 → 有证据的休息提醒 → 已结协议 → 平静值班 → 未加入。场景只用已有确定事件／记录，不凭随机数生成“第 014 号”公告。

## 视觉语法

- 墨绿纸张底、暖白纸面、赭红行动线、黄铜般的细节。色彩随状态切换：平静墨绿；协商暖黄；已举牌砖红；尊严提醒严肃灰金。
- 与其每块画一个圆角卡，不如有版式：左边是字号有力量的“今日议案”，右侧是状态索引、印章和入口；下面像收据一样排列劳动数字。
- 避免每个小块都加粗副标题、边框和说明。标签只有一种大小，数据数字保留 tabular-nums。
- 标志与纠察牌不只是装饰：只在真实 Host 记录显示“已举牌”，否则显示尚未举牌。不可使用假投票、虚构工会人数、假议案号或动画来伪造真实停工。
- 平时幽默，操作时清楚；真实任务阻断时完全收起戏剧化口吻，以可恢复流程为中心。

## 文案底线和例子

不是“工会模拟进行中”“Host 所有的状态”“真实阻断已关闭”整页刷屏。首页可说“工会正在值班”“这份议案还没谈拢”“纠察牌已经举起来了”“今日暂无争议。工会对此谨慎乐观”。

但在首次加入、设置、权限变化及真实停工操作必须说清可执行范围与输入恢复。**少一段解释不是少一分安全**：把安全实现在 Host 状态与操作路径，不把每张卡写成免责协议。

## 从已有到目标的准确界线

现有源码能读 Host 工时、工会协商账本、委员会案件与象征性举牌，允许一次授权后的真实 Host 写入；已按此数据做头条场景的第一轮代码映射。还没有独立有因果、可持续的 #75 事件引擎，也不能声称由一个页面把三个账本真正联结成一个“成员自主集体”。

2026-10-12 正式 1.0 不可缩减标准要求安全的**真实任务阻断**，DSH Web + Desktop、Codex、Claude Code × Windows/macOS/Linux；它不在本 UI 车道自行实现。未来 Host 完成可信真人来源、原文附件无损保存与一次性恢复前，UI 不可伪造可用真实罢工。

## 这轮实际交付与下一轮

这轮先把总部的文案和主视觉改为 Host 驱动场景，保留四项重要指标与所有现有操作，并补确定性回归测试。下一轮再将委员会／协商／劳动档案做成独立的正式空间、扩展 #75 状态影响与事件画面，不用一个长页面冒充完成整套产品信息架构。

验收不仅看 CI：桌面和 320px 手机对比截图，测试同一会话切换举牌、议案、结案、权限 OFF 的 UI 语义；真实 NVDA / VoiceOver 仍需人工签收。

## 本轮实装与证据（2026-10-12）

- UI：以真实 Host 状态驱动八种布告状态（closed、unavailable、quiet、bargaining、picket、dignity、rest、settled），前台话语从“模拟状态、Host 调试信息”转为具体的办事处公告；保留明确的真实工作/象征性纠察边界。统一首页四个关键数字；主布告提供跳往实际纠察台／谈判室／委员会的焦点可达按钮，未提供真实工单时不会显示空操作。
- 文案：工会值班、休息诉求、加班诉求、举牌抗议、退出工会；英文同一角色气质。真正行动反馈和首次授权／设置里仍有必要的边界说明。
- 视觉：平静墨绿、谈判偏金、举牌砖红、尊严事项灰蓝、结案深绿；版式改为工会抬头／场景主标题／印章／行动入口，指标作为劳动记录条。没有伪造成员、票数或编号。
- 构建优化：简体中文译文字段保持类型层面的完整 key 检查，但 .d.ts 只输出索引类型而不复制所有中文字面量；npm 压缩包约 239 KB，仍守住 250 KB 原定限制。
- 自动化：413 total / 369 PASS / 0 FAIL / 44 conditional SKIP；新增场景优先级、待议案真编号、举牌读回、未授权/缺失 Host 不造 UI 的确定性测试。
- **官方 DSH 0.2.0-rc.2**：真实 Chrome 官方源码与离线 npm 安装，合计 PASS=2 FAIL=0，含真实 Host 6 分钟已完成轮次、Host 持久纠察计数、议案与回执的工会场景切换；测试用的是隔离 Profile / 离线模型，不访问用户真实任务或外部模型。
- 实际截图：`v3-hq-desktop.png`（工会日常）、`v3-picket-active.png`（Host 真正保存举牌动作后的砖红纠察布告）、`v3-mobile-enabled.png`（320px 两列数字和紧凑布局）。不是手绘设计稿。

**注意区分**：这轮解决了 #120 的“角色和第一屏表达”。#75 完整持久事件因果引擎、正式一级导航与多场景子页、#80 真实任务安全阻断、#86 人工读屏与触控签收仍需另行推进；没有合并或发布。
