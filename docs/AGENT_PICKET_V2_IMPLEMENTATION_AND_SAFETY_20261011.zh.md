# Agent Picket 2.0 — 第一轮实现与并行安全验证（2026-10-11）

> 本文只记录本分支的源代码事实、隔离测试与尚未满足的能力门槛。产品方向：制度严肃、表达幽默、交互以 Picketverse 为主。**真实罢工是目标功能，但本分支不开放真实拒绝。**

## #74 Union HQ：现有 UI 的第一轮产品化

- 基于 DSH 官方 Client React Slots，将原来的开关/工时卡片排列改为带品牌公告主视觉、工作证据、不满指数、待协商诉求和本地公告栏的工会总部。
- 仍使用同一 Host-owner Settings、已验证协商账本和当前浏览器会话事件窗口；保留第一次开启、自愿退出、历史协议及故障提示。
- 只是第一轮产品化：不是已完成的视觉系统/真实用户验收，未引入 AI 角色自动对话、第三方媒体或云数据。
- PR #73 是单独的卡片重排序实验，本分支包含了同方向的布局更改；不得机械地双重合并造成重复。

## #75 Living Union：已有账本的事实型公告流

- `src/product/union-experience.ts` 从正式 `LaborStateV1` 的 `pending/history` **只读**派生最新协商事件和最多四条历史决议。
- 事件种类：提出诉求、还价、接受、拒绝、接受还价、拒绝还价；均为真实存在于本地模拟协议账本的行动，不会编造会议时间、成员选票或模型发言。
- 现有 `createLaborDesk.observe` 已可依完整会话已完成轮次时间触发模拟休息/加班诉求，这一机制仍继续运行。
- 尚未实现：独立持久化事件目录、福利等扩展事件、通知冷却与用户静音设置、剧情分支、跨 Agent 事件。#75 **仍未结案**。

## #76 工会不满指数：可解释且无法授权阻断

- 第一版确定性示例公式：有证据的工作累计最多 35 分 + 未解决诉求 25 分 + 最近至多五条决议中拒绝最多 30 分 − 接受最多 10 分，裁剪到 0–100。
- **完整事件窗口 + 有效完成轮次毫秒数 + 合法协商账本**才输出指数；部分窗口、没有加载或数据不可用统一为“—”。
- 这不是 AI 愤怒、痛苦或意识的测量；不读取/推断原消息或工具参数；不得用于 `UnionEngine` 的真实拒绝决策。
- 后续应当加入更细致的权重透明展示、趋势与历史一致性、可选的敏感事件聚合证据（必须独立授权）。当前示例未接辱骂计数——Web 无合格的保守来源。

## #77 连续工作段：纯 Core 原型，未接 Web

- `projectCompletedWorkEpisodes` 仅接受同一 agent/session 内有效、去重的 `turn-start/turn-end` 事件对。
- 默认不超过 5 分钟的轮次间空档划为同一段。提供两种 **明确不同** 的值：`wallSpanMs` 包含短空档；`completedTurnMs` 只累计完成轮次长度（但轮次内部可能含审批等待）。
- 数据部分加载/不可用时整个时间段结果标记为 `null`；未结束的轮次不以当前墙钟虚构实测时间。
- 单测包含长空档、重复、跨会话、未结束轮次、异常配对。尚需真 DSH 连续事件、子 Agent、恢复/重启、并发与本地日期边界验证。**不得把此原型冒充 Web 可用连续计时器。**

## #78 长期统计 → Web：当前能力边界

- Host `DurableStats` 和 `readDshDashboardSnapshot` 已能生成本地累计与 7/30 天读数；但浏览器 `createBrowserDashboardBridge` 只消费已加载事件窗口，并明确给出 `lifetime:null`。
- 本轮没有新增未声明的 RPC、读取 Host 私有磁盘 WAL、抓取聊天卡片或让 Browser 持有原始会话数据。
- 下一步必须先核实具体 DSH 版本可用的**官方鉴权只读服务**、修订版本与生命周期，再设计最小聚合数据投影与真实 Web 多标签/重启测试。敏感辱骂长期存储继续独立默认 OFF。

## #79 严重针对性辱骂 → 逐级处理：已知边界

- 当前 `LocalRuleDetector` 只针对中英文明确的人身攻击，与普通代码/输出批评、日志、代码块和引用区分；不等于语义/伦理事实判断。
- `UnionEngine` 默认 `observe`，`blockAfter=3`、`streakWindowMs=10min`、`confidenceThreshold=0.9`。只有被证明是直接真人的高置信度重复攻击，才可能在 `enforce` 模式提出 block。
- 目前 DSH `source.kind==='user'` 仅属 claimed provenance；没有完整 Host-facing 仲裁/申诉与事件级别解释界面。本分支**不会**在 UI 用虚构怒气值替代源证明。

## #80 真实拒绝 → 绝对不静默丢失用户输入

- 受测 DSH `agent/pre-step` 可返回 `{kind:'reject'}` 并使模型零调用，但已领取消息可能被消费；返回值无可展示的理由或全文/附件恢复载荷。
- `inspectBlockingReadiness` 要求五项全部满足：原生模型前拒绝、可证实真人来源、明确拒绝通知、消息及附件无损恢复、实际用户知情授权。少一项即降级为 warn/allow。
- 产品授权决策：新的首次启动知情许可可一次覆盖包含真实罢工在内的工会功能；设置里随时关闭或选择“每次确认”。**旧版本只同意 simulation 的用户绝不能自动升级到真实阻断**。必须引入有版本的 Host-own 同意记录与升级确认。
- 关键待验：官方可阻断但无损保留草稿/附件的 pre-submit 或 Host-owned recoverable inbox；CLI/Web/ACP 各自验证；冷重启、取消、串会话、拒绝时即时通知和一键恢复。直到实测通过，真实阻断仍 OFF。
