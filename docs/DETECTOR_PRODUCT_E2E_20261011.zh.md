# Agent Picket · 自动检测改进与同 Host 实机链（2026-10-11）

> Draft 评审证据；只在 GitHub 源码中保留，**不分发到 npm 用户包**。维持用户一次性明确授权、observe-only、真实请求不阻断、无原文上传。

## 这轮解决什么

原有本地规则容易把讨论/引用一句辱骂误判成对 Agent 的攻击，同时对常见中英文口语漏报。保持原有全部保守回归用例，补充：
- 针对教学、翻译、新闻、引文、例句与语料讨论的上下文前缀；这不是经认证的「非辱骂证明」，它只减少明显误报；
- 中文口语化的第二人称攻击、英文 `you useless bot` / `such an` 等直指对象；语义不明的词保持保守；
- 保持可复核、无第三方模型调用的本地规则，返回值只包含枚举标签和未经校准的启发式置信分。

## 手工挑战样本（不是现实准确率）

本轮对两批先前人工编写的挑战样例做了针对性开发，`tests/detector-challenge.test.ts` 60 条、`tests/detector-context-regression.test.ts` 40 条：
- 第一批 30 正常／上下文样例：原规则 6 次误报 → 当前 0；30 直接攻击样例：原规则 23 次漏报 → 当前 2。
- 第二批 20 正常／上下文样例：首次检验 6 次误报 → 当前 0；20 直接攻击样例：首次检验 10 次漏报 → 当前 1。
- **以上两批现在都是开发回归集，不可当作独立验证，也不能对现实用户外推错误率。**

冻结以上代码后，又另写 12 条正常／引文与 12 条攻击语句，仅诊断一次：**6/12 正常样例误报，8/12 攻击语句漏报**。这组对抗性语言覆盖了未解决的引用范围识别与中英文复杂语法，表明**检测器仍不可靠**。这不是生产抽样，也未用于本轮调参。具体缺口继续留在 Issue #83。

因此，即使一次或多次规则命中也**不代表**已经证明真人滥用、AI 主体意愿或受伤；任何模拟举牌／申诉均由用户显式点击，`agent/pre-step` 永远正常调用 Host 原继续过程，拒绝真实处罚/停工。

## 第一次真正同 Web Host 端到端自动检测

此前 #100/#101 的真实 DSH CommandRuntime/Host Web 分开验收，不能证明正常 API 消息自动经由当前插件的 Host 入口。本轮新增可选环境 `PICKET_DIGNITY_E2E=1`：

1. 测试脚本仅在隔离的 `/tmp` 官方 DSH Web Profile 下安装本地测试专用 `offline-web-provider`。该适配器显式公布一个本地模型，不需要任何在线 API 密钥，也不发 HTTP 请求到外部。
2. 浏览器先完成原有真实 onboarding、授权、全部工时/协商/模拟行动及完整 Host 重启验收，然后用户再次明确开启工会。
3. 浏览器经**同一个 DSH 0.2 正式 Web Host 鉴权 RPC** 创建普通 Session、选择本地测试模型、调用真正 `session/prompt` 接受一条预设、非隐私测试句，进入正式 AgentLoop 而**不是人工直接调用分类器**。
4. 同一个已授权浏览器通过 `/api/agent-picket/dignity/v1` 只读 GET 拉取该 Session 的 SHA-256 会话键记录，验证确实存在目标规则命中、不回传原句；原任务照常运行。
5. 官方 DSH 0.2.0-rc.2 Google Chrome **源码安装与离线 npm 安装两个环境 2/2 PASS**。旧版本 DSH 0.1 维持原版基本验收；该试验不假称其支持同一 Fetch 通道。

**此项还不覆盖**：在这个新 Session 中由用户通过同一 Chrome 工会面板点击立案（该 UI 的完整 Host 写入、结案及重启已由 #102 独立实机验证）；不涵盖所有 ACP/SDK 工具来源、附件字节级重放或独立真人来源认证。#99 保持 Open。

整个新测试对已有精确「两轮六分钟工时」断言有独立时序：额外模拟 LLM 回合必须放在主验收**最后**，不可篡改之前的总工时结果。
