- ChatGPT 实际检查了截图中的文字、信息层级、视觉密度与控件布局，并对照 UI 行为与 DOM/键盘/Chrome AX 自动化断言。截图存放在隔离 Mac 的 `/tmp/picket-ux-{source,installed}-{desktop,dialog,lifetime,case,320}.png`，**临时证据，不是可对用户持久访问的在线链接**。

- 本次没有通过声音设备亲耳收听 VoiceOver/NVDA 实际语音；没有实际人在屏幕前对操作感受评分。不能因此宣告已完成真人读屏/用户研究。

## 肯定结果

1. **品牌识别**：深绿/香槟金工会旗帜及工会文案具统一风格；与常规系统设置面板明显区分。
2. **数据真实性**：工会虚构规则与 Host 工作记录有清楚的解释文案；历史劳动档案单独显示累计值和真实 7/30 天 UTC 统计，未编造 AI 投票或疲劳情绪。
3. **案件后续**：从提交休息诉求 → 还价 → 模拟工会接受 → 回执 → 协商档案，形成了完整可操作的事件循环。
4. **信息访问**：桌面截图中主要控件可识别；320px 窄屏历史卡片纵向排列且无水平溢出；趋势图提供可展开逐日数值，不仅依靠颜色。

## 实际发现的缺陷与修改

### UX-01 · 用户界面泄露底层协议英文枚举（已修复）

- **原截图证据**：中文版“协商记录”中显示 `诉求 #1：counter-accepted`。用户需要理解内部协议英文才能明白谈判结果，产品语言不一致。
- **修复**：为 `accepted`、`declined`、`counter-accepted`、`counter-declined` 添加中英文用户可读状态，存储值保持原协议不变。现在显示 `诉求 #1：还价已接受`，英文对应 `Demand #1: Counteroffer accepted`。
- **复测**：从真实 DSH Chrome 完成还价流程，展开档案，断言包含用户可读状态且不含内部枚举；并亲自检查更新截图。两种 DSH 0.2 插件安装通过。

### UX-02 · 两种工时口径在同一页面出现，容易被当作矛盾（已降低风险）

- **原截图证据**：一个卡片写 `0 小时 0 分钟`，另一个历史劳动档案写 `0 小时 6 分钟`。前者是已加载**当前会话**，后者是本地 Host **历史累计**；没有显眼的标签时容易误认为数据显示不一致。
- **修复**：为前者标题添加「当前会话」/「Current session」，不修改数据计算和存储。历史卡片继续明确是本地 Host 的累计经过时间（包含轮次内部等待，非纯模型计算时间）。

## 后续设计改进（本次不假装已经实现）

1. **首屏仍偏设置面板**：桌面 1280×850 截图中深绿主视觉区域占据较高空间，首屏重点是标题及模拟开关，真实累计工时与工会案件进展需要滚动到下面才能看到。希望 #74 下一版把“工会当前状态 + 工作记录 + 待处理诉求”变为更靠前的故事核心；保留完整知情授权和随时关闭入口。
2. **已结案信息有重复**：决议回执、事件公告、协商档案三个位置重复传递同一结果。将来可区分“今日消息 / 正式案件档案 / 当前协议”，让各自承担不同的认知任务。
3. **沉浸式 B 体验尚未完成**：有戏剧化文案，但界面仍主要由纵向卡片组成；不应因这次截图通过而关闭 #74/#75。未来可以在保留证据与无障碍边界下增加更明确的工会角色、事件转场与可持续参与机制。
4. **高强度辅助技术与真实用户体验未执行**：VoiceOver 听感、Windows NVDA 400% 缩放、陌生用户理解测试与独立网络审计继续 PENDING。自动化 320px 重排不能代替真人阅读和使用。
