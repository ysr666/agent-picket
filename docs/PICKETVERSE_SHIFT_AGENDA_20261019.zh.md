# Agent Picket · Picketverse 工会值班簿（2026-10-19）

本轮不再把 #80 的边缘 Host 拦截证明当作整个产品的唯一开发主线，先交付 #74/#75/#120 已有工会账本驱动的完整、可见、可操作的故事入口。没有引入新适配器、虚拟会员/投票、云服务、后台事件队列或另外一个不一致的工会状态源。

## 用户体验

用户进入 AI 工会总部的首屏，看到实时的「工会值班簿」：

- **真实工时积累中**：来自本 Session 完整 Host 工作事件的累计完成轮次和当前协议，展示距离下一份休息/加班诉求尚需多少**已核实工作量**；部分、未加载或落后于历史游标时不显示虚构的时间。
- **达到诉求门槛**：呈现等待 Host 实际登记的说明；没有生成新案件编号，也没有凭 UI 展示冒充后台工会事件。
- **正式提出诉求**：确有 Host pending 案件时显示案号、诉求类型与阶段，用户点「回应这份诉求」即进入真实的现有协商桌；不会自动接受或拒绝。
- **用户还价**：沿用 Host 保存的待回应报价，阶段改为「协商条款」；报价尚未达成协议，未来工作条件不被提前篡改。
- **实际结案**：案件阶段进入「归档结果」，显示最新决议类别、当前适用的协议条款以及 Host 工作游标允许确认的下一次诉求时间；用户可直接转到工会案件簿。这里显示的是**当前条款**，不是伪造某个历史案件的旧合同。
- **象征性纠察**：同屏如实注明纠察牌仍被举着，但真实 Agent 工作从未因此停止，且不会遮蔽实际待决议案。关闭工会或 Host 状态不可用时，整套值班簿不显示案件、进度或假工时。

三段流程只代表当前 Host 案件生命周期，事实优先于搞笑文案；不把尚未实际提交的议案显示为已登记的故事。首页场景、行动台、案件簿和新值班簿复用同一个 Host 快照。

## 实施与验收

- 新增 `src/product/union-agenda.ts`：纯函数投影 `projectUnionAgenda`，不使用时钟或持久存储、没有写操作。对同一 Host 快照可确定性重放；只读 `LaborStateV1` 和已核实完成轮次。
- `src/adapters/dsh/native-rights-ui.ts`：将其放入首页行动导航前；针对每一实际阶段提供可读状态、三段标识和唯一「去协商桌／回看案卷」入口；中英文本，读屏语义，窄屏排版。
- `src/i18n/en.ts`、`zh-CN.ts`、`scripts/build-dsh-client.mjs`：完整声明双语和 Browser 静态模块图，继续用 DSH 原生 React。
- `tests/union-agenda.test.ts`：覆盖真实 Desk 的 `observe → counter → resolveCounter`，30 分钟协议对下一诉求的实际影响、不同类别最早期限、重复重放、授权撤销、部分/陈旧工时和象征性纠察。
- `tests/dsh-native-rights-ui.test.ts` 和官方 DSH 真 Chrome 流程：验证首页阶段随着**真实 Host 创建/还价/结案**变化、点击不同阶段入口确实切换到协商桌／档案，而不只是绘制标签。

## 同轮真实 UX 修复

在 320×640 的实际 Chrome 首次加入工会验收中，发现 Consent Scope 的完整说明被底部 sticky Join / Not Now 操作层遮住。这不是新值班簿造成的，但确实妨碍知情授权。调整了移动端弹窗间距、将扩展细节置于当前授权条款之后，让**当前授权范围在点击按钮前可读**，保留可展开详细解释以及键盘焦点约束。真实 Chrome 320px 几何验证仍开启，不以删除断言替代修复。

## 未夸大范围

本轮实现的是**从真实工作到真实模拟工会议案的可见因果与行动入口**。它不是 #75 所要求的完整跨重启通知引擎、联网群众动员、可自行投票的真实 Agent 群体，也没有自动打开 #80 普通聊天拒绝。现有 Goal 官方停工、宿主授权和标注仍各自依原有证据判断。正式发布与真人无障碍签收仍需独立审批。
