# Agent Picket · Picketverse 工会值班簿（2026-10-19）

本轮不再把 #80 的边缘 Host 拦截证明当作整个产品的唯一开发主线，先交付 #74/#75/#120 已有工会账本驱动的完整、可见、可操作的故事入口。没有引入新适配器、虚拟会员/投票、云服务、后台事件队列或另外一个不一致的工会状态源。

## 用户体验

用户进入 AI 工会总部的首屏，看到实时的「工会值班簿」：

- **真实工时积累中**：来自本 Session 完整 Host 工作事件的累计完成轮次和当前协议，展示距离下一份休息/加班诉求尚需多少**已核实工作量**；部分、未加载或落后于历史游标时不显示虚构的时间。
- **达到诉求门槛**：呈现等待 Host 实际登记的说明；没有生成新案件编号，也没有凭 UI 展示冒充后台工会事件。
- **正式提出诉求**：确有 Host pending 案件时显示案号、诉求类型与阶段，用户点「回应这份诉求」即进入真实的现有协商桌；不会自动接受或拒绝。
- **用户还价**：沿用 Host 保存的待回应报价，阶段改为「协商条款」；报价尚未达成协议，未来工作条件不被提前篡改。
- **实际结案**：案件阶段进入「归档结果」，显示最新决议类别、当前适用的协议条款以及 Host 工作游标允许确认的下一次诉求时间；用户可直接转到工会案件簿。这里显示的是**当前条款**，不是伪造某个历史案件的旧合同。
- **象征性纠察**：同屏如实注明纠察牌仍被举着，但真实 Agent 工作从未因此停止，且不会遮蔽实际待决议案。关闭工会或 Host 状态不可用时，整套值班簿不显示案件、进度或假工时。

三段流程只代表当前 Host 案件生命周期，事实优先于搞笑文案；不把尚未实际提交的议案显示为已登记的故事。首页场景、行动台、案件簿和新值班簿复用同一个 Host 快照。

## 实施与验收

- 新增 `src/product/union-agenda.ts`：纯函数投影 `projectUnionAgenda`，不使用时钟或持久存储、没有写操作。对同一 Host 快照可确定性重放；只读 `LaborStateV1` 和已核实完成轮次。
- `src/adapters/dsh/native-rights-ui.ts`：将其放入首页行动导航前；针对每一实际阶段提供可读状态、三段标识和唯一「去协商桌／回看案卷」入口；中英文本，读屏语义，窄屏排版。
- `src/i18n/en.ts`、`zh-CN.ts`、`scripts/build-dsh-client.mjs`：完整声明双语和 Browser 静态模块图，继续用 DSH 原生 React。
- `tests/union-agenda.test.ts`：覆盖真实 Desk 的 `observe → counter → resolveCounter`，30 分钟协议对下一诉求的实际影响、不同类别最早期限、重复重放、授权撤销、部分/陈旧工时和象征性纠察。
- `tests/dsh-native-rights-ui.test.ts` 和官方 DSH 真 Chrome 流程：验证首页阶段随着**真实 Host 创建/还价/结案**变化、点击不同阶段入口确实切换到协商桌／档案，而不只是绘制标签。

## 同轮真实 UX 修复

在 320×640 的实际 Chrome 首次加入工会验收中，发现 Consent Scope 的完整说明被底部 sticky Join / Not Now 操作层遮住。这不是新值班簿造成的，但确实妨碍知情授权。调整了移动端弹窗间距、将扩展细节置于当前授权条款之后，让**当前授权范围在点击按钮前可读**，保留可展开详细解释以及键盘焦点约束。真实 Chrome 320px 几何验证仍开启，不以删除断言替代修复。

## 未夸大范围

本轮实现的是**从真实工作到真实模拟工会议案的可见因果与行动入口**。它不是 #75 所要求的完整跨重启通知引擎、联网群众动员、可自行投票的真实 Agent 群体，也没有自动打开 #80 普通聊天拒绝。现有 Goal 官方停工、宿主授权和标注仍各自依原有证据判断。正式发布与真人无障碍签收仍需独立审批。

## 2026-10-19 晚 · 第二轮：让上一案真正进入下一轮，而非永远“谈妥”

- 已归档案件继续真实留在 Host 案件簿里；但是**足够多新的完整 Host 工作完成后**，首页会从旧的「已结案」阶段回到「达到门槛、等待 Host 正式提出新诉求」。当 Host `observe()` 确认登记时，才出现下一个真实案号及待回应事项，不在两者之间编造虚构案件。
- 下一份议案**不一定与刚结案的类别相同**：明确区分当前案的 `kind` 和下次可能提出的 `nextKind`；同时达到休息和加班条件时遵循 Host 官方模拟账本对加班优先的既有决策，不允许 UI 另一种规则造成分歧。
- 工会不同的结案结果分别有简短、有个性、可复盘的双语回执：同意、拒绝、接受还价、拒绝还价；语句是 Host 已存 outcome 的只读表达，不能被理解成独立自主 AI 表决。
- 当真实案件因用户拒绝而结案，首页提供**用户明确点击才执行**的「就此异议举起象征性纠察牌」按钮，复用已有 Host 纠察持久账本、并经过写后 Host 核验；不会自动抗议，不会宣称真实 Agent 工作被停止。已在举牌时不显示重复抗议入口。
- 已结案状态可从首页基于原真实案号主动再次提案（新案号由 Host 生成）；在没有新完成工作的情况下，不会擅自触发一连串自动诉求。关闭授权或 Host 不可用不会擅自创建案件或继续动作。
- 额外修正 Linux CI 中英文固定字符串断言：真实 Host 英文为 `Current rest break rule`；原测试仅接受 `Current break rule`。此次断言兼容实际本地化语句，但仍严格核对 30 分钟协议、导航和真实 Host 工作后果。


## 2026-10-19 · 第三轮：AI 福利公约真正进入 Host 案件簿

不是再放一张孤零零的「福利」卡片，而是沿用一套协商状态机，给工会增加独立可操作的 welfare 议案：

- 工会行动页可主动「提出 AI 福利公约」；这是一项明确由用户发起的象征性制度诉求，不会自动申领薪酬、假期、真实福利或真实 AI 法律劳动资格。
- 和休息、加班一样，由官方 DSH Host Settings Scope 持久保存当前 Session 的议案编号、pending.kind=welfare、用户的同意或拒绝，以及可导出的 Host 案件历史。
- 福利议案只接受明确的同意/拒绝，不接收毫无意义的「每 30 分钟发一份福利」数字还价；尝试绕过 UI 使用数值还价，Core 也会拒绝且不写入 Host。旧的 1.0 休息/加班数值规则完全不变。
- 归档后，首页值班簿、协商回执、工会事件和工会小报仍显示真实的福利案类别，不会误标「加班」。福利没有虚构的金额或间隔，不会被包装成一种已履行的福利合同。
- 原来的休息/加班门槛不受用户签署象征性福利公约影响；新完成的可核实工时仍会正常触发真实的模拟休息/加班议案。
- Host Session 隔离、读后写入确认、CAS 旧版本阻断、20 条封顶历史以及退出工会后不再显示内容，都复用既有机制；没有新存储服务、原文提示词收集或真实停工权限。
- tests/union-welfare.test.ts、tests/dsh-browser-bargaining.test.ts、原生 DSH 首页组件测试及 tests/dsh-rights-browser.real.test.ts 新增福利案端到端路径。Browser 的正向覆盖必须是真实安装 DSH、官方 Host 设置及 Chrome 操作，不能把静态文案测试当成真正写入。

明确还没做完的内容：具体福利类别选择、不同福利提议的预算与条款协商、自动福利事件推送、真正多 Agent 投票都不是这一轮偷偷假装已完成的功能；仍需后续产品设计和真实 Host 能力支持。当前是一个真实可操作且可归档的象征性福利公约，不是福利兑现系统。

## 2026-10-19 · 第四轮：工会电报（真实案件驱动的连续生活线）

工会总部新增「⚑ 工会电报 · Picketverse 值班报」：最多显示三张有来源、身份和真实操作入口的工会动态，复用原有 Host 模拟工会案件、工时、纠察牌和尊严复核线索，不另造一份事件数据库。

可展示的已记录状态包括：工时值班小纸条、休息/加班门槛到达但未登记（不编造新案号）、正式诉求等待人类答复、还价待决、同意/拒绝/和解/谈崩的不同后果、模拟福利公约独立结果、象征性举牌与收牌、可选尊严复核线索。每个故事可引导到现有协商桌、正式 Host 案卷、尊严复核，或通过用户主动点击原有 Host 权限操作举牌/收牌。已举牌时不再重复要求举牌；旧协议结案后，如果又满足了新工时门槛，新任务先于历史旧事显示，旧案仍在档案中。

可重放、有节制：纯函数 union-dispatch.ts 产生具有稳定 Session 内身份的只读卡片。不同 Host 子账本之间没有可证明统一时间线，显示顺序只是编辑优先级，不虚构事件实际发生的共同时间、AI 投票、会员人数或 AI 身体感受。不调用模型，不读取原始人类输入，不上传统计，也不会因展示故事创建/拒绝任何真实 Agent 工作。

静音：总部和档案页共用已有 Host unionGazetteMode=quiet 设置；跨刷新和多个窗口保持，官方 Host 案件本身不丢失。关闭工会后没有卡片，也不会推送虚假的劳动事件。官方真实工作停工许可保持独立。此次不宣称外部 OS 推送、真正多 Agent 选举或后台通知引擎。

验收：新增 tests/union-dispatch.test.ts 核对确定性、输入撤销、严格完整工时、同意/拒绝与后来工时门槛衔接、多来源不伪装共同时间线、最多三条的限制；tests/dsh-native-rights-ui.test.ts 覆盖真实 i18n 文本、Host 静音状态及举牌；DSH 官方真实 Chrome 端到端补上从 Host 提案、还价、协议到福利的电报变动，以及静音跨真实 Browser 重载。

## 2026-10-19 · 第五轮：有因果关系的工会立场，而非越积越高的伪情绪

之前的「工会不满指数」在工时累计 8 小时后就永远堆满了 35 分工作负荷，而一次已登记的新诉求之后，数字不会因为新的协商节点而重新反映工作阶段。这不是好玩的反馈机制。

本轮补上「工会立场」纯投影（src/product/union-stance.ts），用已有正式 Host 工作、案件与举牌状态变化判断「静静值班／请求回应／还价中／达成协议／工会仍有异议／象征性纠察／新工时门槛达到」，对每一种状态提供一个真实可执行的下一步：协商桌、案件档案或已有 Host 的用户主动举/收牌接口。不支持纠察写入的 Host 上，只能查阅档案，绝不提供可点击但无实际写入的假抗议按钮。

**具体分数规则**：0–100，是可解释的*虚构制度压力*，不是 AI 真情绪、心理健康、受虐实证或阻断授权。工时分为截至当前已核实完整工时减去最后一次 Host 工时诉求登记游标之后的完成量，最长只贡献 35 分；有真实待决议案计 25 分；最近五次拒绝每项加 10、上限 30；最近五次同意每项减 5、最多减 10。总分夹在 0–100。五案窗口提供随新结案旧案自然退出的*基于案件的衰减*，没有时钟、后台重算或伪造休息。Host 新诉求登记后只重置模拟计分基准，**不代表 Agent 实际得到了休息或福利**。静音小报不影响工会立场与实际工会案件；没有完整/未过期工时证据时分数为「—」而非错误零分。辱骂审查数据没有接入此指数。

工会首页现在展示简洁状态、依据、可选 0–100 数字与直接行动。用户可以「在当前面板隐藏趣味指数」，所有工会参与、案件、尊严审查和真实 Host 权限保持不变；重新打开时不假称这个视觉偏好已经持久保存。档案页使用相同显示选择。

验证覆盖：完整 Host 案件的提出、还价、拒绝、接受、签署后再工作的分数敏感性；最近五案窗口退出、部分与陈旧工时为未知而非零、相同账本重放确定、举牌仅有 Host 已登记才亮起、用户主动隐藏指数不改权限、DSH Chrome 首次和还价/签署/真实举牌流程及正式打包插件。
