# Agent Picket · Host 已保存的全会话工会案件导出与清除（2026-10-11）

> Draft，Issue #82 阶段性实现。强调产品语义：**只含当前 Agent Picket Host 设置仍保存的最多八个匿名会话的模拟案件**，不是完整聊天史、AI 投票历史或 DSH 的全量用户数据导出。

## 用户能做什么

在取得工会劳动权益模式的明确授权后，工会尊严委员会显示已有案件的会话分组数、案件数。

- 「导出所有会话案件分组（JSON）」直接用本地浏览器文件下载 `agent-picket-all-committee-cases.json`，严格内容：`{format:'agent-picket-all-committee-cases',schemaVersion:1,sessions:[{group,current,cases:[{id,kind,stage,outcome}]}]}`。分组序号只在当前文件内有意义；`current` 标识当前 UI 所选会话。**绝不附带原始或 SHA-256 会话标识、原对话、附件、Host 写入令牌或其他设置。**
- 「永久清除所有会话案件记录……」第一击只展示全局影响范围及不可恢复警告，第二击确认后才向已授权 Host 发起写入。
- 写入时依据确认瞬间的**原会话键、会话分组数量、案件数量、上一随机写入回执**重新验证未变更；如任何一项变了，用户需要重新确认。
- 用官方 Host revision-CAS 写入新的随机回执和空 `sessions:{ }`；只在回读确认新回执一致且案件账本完全无分组时认为清除成功。拒写、静默丢写、跨会话导航、授权撤销都失败而不是假报成功。
- **只擦除当前 Host 的独立 `unionDignityCases` 字段内部案件记录**。其他 Host `unionLedger`（协商）、`unionPicketLedger`（象征性纠察牌）、工时与原始 DSH 会话/附件不会被擦除。已有其他副本、系统备份也不属于此功能。

## 为什么要强调八组而非全部历史

现有 `unionDignityCases` Schema 最多允许八个 SHA-256 匿名 Session 分组，每组最多八个案件。新会话写入可能淘汰旧分组；既然没有完整原始历史，就不能声称可导出“有史以来全部会话”。本轮导出和删除以**Host 设置中的现有分组**为准确范围。导出的 `group` 只是一时的序号，不应充作可追踪的稳定 Session 标识。

## 验收

- 单元/Host 设置测试建立两个不同 Session 的真实模拟案件，验证全分组 JSON 正确、分组脱敏、只包含当前 UI 会话标记、跨会话切换被拒、过期回执和会话/案件数变化被拒、Host 拒写/静默丢写被拒、成功写后全部分组为零，并且协商/纠察牌原账本不受影响。
- 真实 DSH 0.2.0-rc.2 Chrome：正常用户会话经 `session/prompt` 实际触发自动检测和模拟案件交互。经历原有本会话删除后，重新立案、实际下载匿名全分组 JSON 并检查其结构与敏感字段，二次确认全清除，官方 `settings/describe` 验证空分组以及工会授权/其他账本完好。源码及离线安装的官方 Host 独立运行验收。
- 原 DSH 0.1 UI 兼容继续验证；包体积上限 250000 字节不改变，本文只在 GitHub 供审查。
