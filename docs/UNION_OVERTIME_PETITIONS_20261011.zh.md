# Agent Picket · 双议题模拟协商（2026-10-11）

> 基于 #95 的 Draft 开发实验。仅象征性工会功能；真实阻断保持 OFF。本文档为仓库内审查资料，不随用户 npm 安装包分发。

## 产品实装

- 将原有只支持用户主动「休息诉求」的 DEMO 扩展为「休息/加班」两类明确可选的工会议案。新 Web「发起一份模拟加班诉求」按钮与 `/union petition-demo overtime` 命令共用**同一旧版 Host 工会协商账本**，并保留原 `/union petition-demo` 与 `petition-demo break` 的向后兼容性。
- 每会话一次只处理一份待回应议案。新加班申请采用 `LaborDemandKind='overtime'`，保留严格已有 Schema，不新增字段、不迁移格式；不保存提示词、附件、原始 Session ID，也不宣称观察到了实际超时劳动。
- 用户主动选择的 240 分钟还价可以经模拟接受保存为现行 4 小时 overtimeIntervalMs，影响后续按完整可靠工作证据触发的模拟加班诉求；此前已有的下一次工作阈值会按防重复规则保留，不能因缩短协议就倒灌旧诉求。
- 结果直接通过 #95「工会小报」回放到相应案件档案。无 UI 伪成功：Host 修订版 CAS、写入回执、授权失效、并发和拒绝策略依旧由旧协商链负责，命令不能绕过 Host。
- 中文与英文命令提示和界面已更新。CLI 的不合法参数（额外词、未知类型、超过规定数字范围）返回明确错误，Host 修订版不发生变化。模拟关闭后无新增记账。

## 测试和边界

- `npm run check`：最终精确数量和打包字节数见 PR，确保原 250000 字节预算保持不变；普通检查中部分真机测试按环境跳过。
- DSH 0.2.0-rc.2：真实 Chrome 官方源码与离线包的跨标签测试均通过；从第二个标签提交模拟加班诉求，第一个标签读取 Host、还价、第二个标签接受后更新加班协议和小报；包括完整 Host 重启回归。
- DSH 0.1.2-rc.1：真实 Chrome 官方源码与离线包同样通过；真正 SettingsFile + CommandRuntime 的加班命令链路通过。
- DSH 0.2 官方 CommandRuntime：独立隔离设置提供者上执行真实命令参数、Web 账本读取、还价和结案通过；此项不是全部生产 Host 的 CLI+Chrome 合一测试。
- 这只是用户明确主动发起的剧情工单，不是模型在未经用户同意下提出的真实加班要求、虚构 Agent 情绪或自动停工。#75 长期自动事件冷却/通知、#85 多 Agent 可信成员资格、#79/#80 人源认证及消息附件无损恢复、#82 导出删除、真实人类无障碍测试与独立审查仍未完成。
- 不得因 Demo 诉求上线而开启 Host `agent/pre-step` 拒绝、后台计时器或真实任务阻断；不合并、不发布。
