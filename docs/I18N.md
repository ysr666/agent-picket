# Agent Picket localization contract (Issue #28 foundation)

This change provides an **additive, Host-neutral localization module**. It does not change the Union Core policy, start a Web UI, persist Host settings, or enable simulated / real task blocking. Both English (`en`) and Simplified Chinese (`zh-CN`) have the same set of initial app/onboarding/union-first/workday/stats/safety messages.

## API

```ts
import { resolveLocale, formatMessage, formatPlural, formatElapsed,
  createLocaleController } from '../src/i18n/index.ts'

const locale = resolveLocale({ preference: 'auto', hostLocale: 'zh-CN', systemLocale: 'en-US' })
formatMessage(locale, 'union.demand.overtime')
formatMessage(locale, 'workday.elapsed', { duration: formatElapsed(locale, 180_000) })
formatPlural(locale, 2, { one: 'stats.turns.one', other: 'stats.turns.other' })

// Settings owner must implement real, safe storage in the Host.
const language = createLocaleController({ store: hostSettings, hostLocale: getHostLocale })
// language.setPreference('en') writes, reads back, or throws. No false success.
```

Locale precedence: explicit preference > trusted Host locale > system locale > English fallback. `auto` means follow Host/system. `zh-TW` / `zh-Hant` deliberately do **not** select Simplified Chinese.

## Integration guidance for other PRs

- **Core policy decisions remain structural data**, not translations; only command/UI/Host notification adapters should call `formatMessage`.
- New UI #29 must use a separate **authorized settings owner** for locale and simulation consent. This module defines an injected `LocalePreferenceStore` contract, **not** a production settings writer or unapproved DSH RPC.
- DSH Web #35's `agentPicketDashboard` is read-only session **numbers with coverage**, not preferences, lifetime stats or rights-event persistence. UI #36 must not use it to save state.
- Real task blocking remains unavailable/off until separate #32 authorization and verified Host recovery. The button to enable nonblocking Labor Rights Simulation does not authorize blocking.
- Never render interpolated localized text as raw HTML. Use `textContent`, normal framework text interpolation, or equivalent escaping.
- Use message keys and structured parameters for union voice, not human-visible strings as state identifiers.

## Adding a locale

1. Add a complete typed catalog under `src/i18n/` with exactly the English keys and identical `{placeholder}` names.
2. Extend `SUPPORTED_LOCALES`, `catalogs`, and `normalizeLocale` with **deliberate** mappings for the new language/script. Do not equate zh-Hant with zh-CN.
3. Add plural-aware forms where needed; `Intl.PluralRules` determines `one` versus `other`. For richer plural categories, extend the API/tests first.
4. Add tests for fallback, every key, placeholder parity, number/date/unit formats, safety and dialogue wording. No automatic translation of chat content.
5. Check actual DSH CLI/Browser outputs (and future Claude/Codex adapters) after they are merged; do not claim the entire plugin is localized until each user-facing surface uses this module.

## Current limitation

The baseline `main` DSH command strings remain unchanged to avoid conflicting with the unmerged DSH plugin and Companion stack. This is **foundation code**, not complete Issue #28 acceptance. After integration review, translate those user-facing surfaces and add verified per-Host preference persistence. No automated UI/a11y test is claimed here.
