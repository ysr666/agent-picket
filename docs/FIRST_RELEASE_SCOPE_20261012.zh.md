# Agent Picket · 首发收敛与实际阻断准入（2026-10-12）

## 发布决策，不是技术假装

Agent Picket 首发需要有真正可用的权益流程，而不是工时统计器。工会、诉求、协商、非阻断举牌必须保留。以 DSH 0.2.0-rc.2 作为首发 Host 基线，不把未验证的 Codex/Claude Hook 当成已支持的适配器。

当前已实现的首发候选：

- 授权后读取官方 Host 已完成轮次时长。超过**当日 UTC 8 小时累计**，显示工会休息建议；超过**本会话 2 小时累计**，显示阶段性休息建议。数据包含轮次内等待，不是连续工作或模型运算时间。Host 记录不可用时绝不补造数值。
- 授权后读取当前会话内存中的本地措辞规则结论，显示有歧义 / 针对性措辞的讨论邀请。来源只是 Host 声称的 user-source，不证明真实作者身份，不自动作出处罚。
- 通知仅是工会总部可见的、可用键盘打开协商桌/尊严委员会的非阻断提示。**没有系统/桌面推送通知，不会在界面关闭时弹窗，也没有真实任务拦截。** 不保存原始文本和附件。
- 用户仍可在可用的 Host 档案中协商休息与加班诉求、作出决定、查看回执，自愿举牌和收牌。纠察属于象征性行动，任务照常执行。

## 实际阻断的不可绕过条件（Issue #80）

DSH 0.2.0-rc.2 的 `agent/pre-step` 物理 reject 可以令模型不执行，但没有验证过的、第三方插件可用的「事先保留完整输入和全部附件 → 说明原因 → 用户恢复/放行 → 恰好一次继续」接口，且事件的 claimed-user 并非 verified-human。因此**真实自动拦截继续 OFF**，不得把 reject 当成可交付产品。严禁建一个插件自有的原始 Prompt 缓存来绕过 Host 限制。

解除 No-Go 需证明：正式 Host 可暂停/恢复提交且原始文档与附件字节保持一致、真实人类来源可核验、明确警告/异议/放行、崩溃与跨标签保持一致、授权可随时撤销，并在支持的正式 Host 的源码/离线端到端测试均完成。未满足则只能继续非阻断提醒。

## 建议的首发门槛与节奏

**A · 公开预览版（不含真实阻断）**：以 2026-10-19 至 10-26 为目标窗口，不是预先批准发布。前提是安装说明和截图更新、完整自动化和 Chrome 验收通过、实际双语首次使用和触屏至少完成基础验收、敏感措辞误报复核完成、README 明示非阻断。提交现有 Draft PR #110 后等待负责人明确同意合并、Tag 和 npm 发布。

**B · 首版强制要求真实阻断**：暂不承诺日期。先推动 Host 提供原生可恢复的暂停提交能力，实测 #80 的所有 No-Go 指标，再决定正式版本计划。可以提前实现 Host-neutral 的警告/升级/申诉状态机及测试，但不能在现有 DSH 上接入未经验证的物理 reject。

不能将「自动化通过」等同真人无障碍测试签收。不要为了首发反复研究未发布旧数据迁移，也不要将 0.2.1-alpha.2 未验证 API 宣称正式支持。
