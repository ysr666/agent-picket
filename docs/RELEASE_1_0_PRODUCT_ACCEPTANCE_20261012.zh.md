> 2026-10-12，集成分支 `integration/agent-picket-1.0-20261012` 的**人工验收工作底稿**。不是一次已经完成的用户研究；未完成项必须保留 NO-GO。优先依据 `docs/UNION_PARTICIPATION_V1.zh.md`、`docs/AGENT_PICKET_V2_IMPLEMENTATION_AND_SAFETY_20261011.zh.md`、最初 Roadmap 与 Issues #74、#75、#79、#80、#83、#84、#86。

## 发布北极星：这个项目不是 AI 统计面板

用户在第一次进入的 30 秒里必须看见「AI 工会是谁、目前做什么、用户能参与什么」，累计劳动时长、检测计数只是证据，而不是产品主角。幽默与标语不代表 Agent 真有主体意识、外部工会法人身份或真实投票。任何模拟举牌都明确告知**用户的真实任务照常运行**。

产品已经确定：首次明确 Host 授权一次，默认关闭；象征性举牌授权后单击执行，Host 回执确认；设置里可撤销。绝不能强制加入第二次象征性举牌确认。不可逆删除则单独确认并绑定用户看见的 Host 账本版本。真实罢工的授权和技术门禁不同：旧版模拟许可不能升级成真实拦截许可，#80 未过时一律 OFF。

## 在真实隔离 DSH Profile 里要完成的人工操作脚本

1. **首次授权，30 秒理解**：从未启用的 Host/空 Profile 开始，不提示答案，让第一次看到产品的人说出工会身份、象征性行为、统计与真实任务的关系。记录原话、困惑位置、中文和英语各一次。拒绝授权后 UI 不能误显示正在举牌。
2. **两分钟参与闭环**：已开启工会后，主动提出休息/加班议题 → 查看 Host 案件编号 → 接受或反提案 → 结案 → 验证未来阈值改变和 Gazette/协议回执。重载、多标签后仍须能看到相同 Host 结果，绝不编造 AI 投票。
3. **辱骂误判申诉路径**：用明显技术批评、被引用的攻击性语句和模拟测试字符串输入，检查只把规则匹配说成疑点而非真人有罪。点击「质疑规则判断」**必须把实际焦点送到未提交草稿**；正式立案必须另行由用户点击，确认完整的模拟听证与可撤回路径。
4. **举牌与收牌**：首次授权一次后，单击完成象征性举牌或收牌；所有入口统一 Host 回执，屏幕显示的是模拟动作，真实 Agent 输入+附件不丢、不暂停。不得出现强制二次确认。
5. **拒绝、撤销和重授权**：设置关闭后 CLI/Web/机器可读快照同时清空、拒绝新工会动作；临时分类缓存消失，原有持久案件不会因关闭就暗中删除；重新开启时工时/尊严计数须新鲜读取，不显示旧权限的结果。
6. **隐私与数据所有权**：导出并检查 JSON 只有许可的数值与案件字段，不含原始提示词、Session ID、附件、令牌；不可恢复删除才两次确认，另一个标签修改案件后旧确认必须失效；原 DSH 对话与独立工作统计不能被误删。
7. **键盘/读屏/缩放**：完整 Tab 顺序、焦点不丢失、对话框 Escape 和回到发起按钮；在 NVDA/VoiceOver 的真实设备、320px 宽、200%/400% 缩放、系统强制色、中文/英文下分别记录是否能完成前六步。发现任一无法访问的动作必须标为 NO-GO。

每项保存最少一份脱敏证据：确切的 DSH/Agent Picket 提交版本、Host Profile 配置、使用者是否熟悉产品、实际步骤及结果、失败重现方式和需要处理的 Issue。**用户本人、测试者或产品维护者确认以前不得替他们写 PASS。**

## 本次集成候选的产品改进

- #79 非惩罚性申诉草稿捷径此前只在长页面下方静默切换选题。现在点击后聚焦到**实际的议题标题**（标题 `tabIndex=-1`，不增加日常 Tab 位置），读屏/键盘用户能够发现下方未提交草稿；仍没有自动提交或虚构申诉。
- 工作档案此前在同一 Session 的后续完成轮次只显示旧 Fetch 结果，除非用户手动刷新。现在仅在 Host 已完整观察到新的 `turn/end` 数时请求更新：背景与打开的工会抽屉共用一个去重门，工具事件、设置通知或浏览器空闲时间均不会制造更新；保留用户已选择的 7 天或 30 天统计视图。官方 Host 权限 OFF 时不再请求该只读接口。

以上是**代码级/自动化级变化**；不表示完整真人验收已通过。

## 发行结论

**当前 NO-GO。** 自动化和两版 DSH 真实浏览器仅证实特定路径可用。产品主线及未完成的 #80、#83、#86 和独立审计必须在正式 1.0 范围/发布审查里逐项决定。PR #110 仍是 Draft，不能擅自合并、加 1.0 Tag 或公开发布。

## 2026-10-12 · #82 命令行账本可携带性（仍需真人验收）

CLI /union export negotiations|pickets|cases 后须明确提供一个不存在的绝对 .json 目标路径；从官方、已授权、当前可用的 Host 账本按类生成版本化 JSON 文件，仅包含带序号的分组、是否当前分组和明确验证过的协议／象征性行动／委员会案件字段；没有原始或哈希 Session ID、Agent ID、写入令牌、原文或附件。空／关闭／不可用状态只返回错误，不伪造空历史为成功导出。

CLI /union purge negotiations|pickets|cases ALL CONFIRM 显式说明整个选中类别的所有已保留 Session 分组将被删除；Host 版本 CAS + 独立 writeToken 回读必须成功，才报告删除完成。删除 A 类不触碰 B/C 类和 DSH 自己的聊天。命令行不会提供无范围的 /union purge all，以免跨类别多次写入被误以为原子事务。关闭授权后不允许导出或删除；恢复授权也不能自动删除既有记录。

这尚未关闭 #82：现有 /union forget-lifetime CONFIRM 单独处理本地跨重启工作统计；没有把其当作 Host 三类账本的原子删除。内存的计数器可通过 /union reset 清理当前会话；系统备份、DSH 对话文件与外部已下载 JSON 不在本插件擦除范围。完整各类冷启动恢复、真实跨标签冲突、所有 DSH Host 版本，以及真人删除理解与可访问性仍需签收。

## 2026-10-12 新增独立 P0：#111 Host 多所有者真实数据丢失

**独立 DSH Host 所有者共用一个 Host 配置文件不能视为已经支持。** 已在隔离 DSH 0.1.2 中复现：两套独立的 Host SettingsFile 所有者 A、B 先后对同一文件写入举牌和休息诉求，各自报告成功，重新打开后 A 的原举牌丢失；默认 watcher 开启时也会发生。见 #111 和可显式启用的失败测试。它不同于同一个 Host 下面的两个 Web 标签页。正式 1.0 支持声明、帮助文档与多实例安装行为必须据此受限，直到 Host 所有者唯一性/真正跨所有者原子 CAS 被证实。

**已实际通过的部分**：一个真实 Host owner 在一轮使用和多次完全卸载/重启期间，两个 Session、三种用户工会档案类型的分离写入、独立类别删除与再次加载全部通过；不代表突然断电后的物理持久性、系统备份或跨独立 Host owner 的原子写入。项目还需真人同意已存储工会记录中的匿名分组是 Session ID 的 SHA-256 哈希，而不是不可关联的匿名标识。

### #111 的进一步验证：撤销和删除可复活（真正跨 OS 进程）

真实独立 OS 进程测试不只复现举牌丢失，还复现两项 P0：已确认分类删除的 Host 举牌档案因另一进程旧缓存写入而再次出现，已确认 OFF 的 welcomeDecision 也因另一进程旧缓存写入而恢复 enabled。本地固定环境 watch:true，三个显式失败门禁和顺序进程重启成功对照已记录于 #111。直到 Host 根因修复或发行明确保证独立 Host 配置所有者唯一性，不能对跨独立所有者的删除/授权撤销提供安全承诺。正常 CI 的跳过测试并不是验收成功。

### 2026-10-12 · #82 CLI 导出的 DSH Session 日志副本风险与解决

审查真实 DSH 0.1.2 / 0.2.0 CommandRuntime 后确认：命令定义的 recordInput:false 仅阻止保存输入参数，不能阻止 command/done.text 被记入普通 DSH 会话。先前将完整档案 JSON 当作 /union export 命令返回文本，实际上会在 Host 原生会话日志产生一份**不由工会分类删除管理的档案副本**，与“删除后不保留其他副本”的直觉相冲突。

现 CLI 导出要求用户**明确给出目标文件的绝对路径**，使用独占创建模式（不覆盖已存在文件或软链接），POSIX 权限 0600。命令结果及 DSH Session 日志只显示脱敏的普通成功或失败提示，不含完整档案正文或目标路径。文件由用户主动管理；/union purge 不会替用户擦掉已经导出的文件或任何 Host 原生日志。网页版原有 Blob 下载模式不受影响。

真人需再次验收“绝对路径”“已存在文件拒绝覆盖”“删除工会账本不删除用户下载副本”的认知和多语言指引。受测 macOS 上实际 DSH 0.1.2/0.2.0 CommandRuntime 的 command/done 事件已新增不含正文的自动化断言；不代表所有未知 DSH 变体、系统备份或第三方插件均有相同日志策略。

### 2026-10-12 · 旧版账本也有可靠的删除授权版本约束

现代 Host 账本依赖每次改动产生的随机 writeToken，使二次点击删除确认在数据变化后失效。合法旧版账本有可能缺少这一 token：现在非空旧版记录的删除操作同时要求确认时的**同一 Host 设置修订号**，版本无法读取时拒绝执行。当前会话案件、全部案件、举牌和协商档案均使用统一原则，UI 界面也会在 Host 版本变化时撤销旧的删除按钮状态。确认流程仍是仅删除不可逆数据才两次点击，象征性举牌不额外索要授权。跨独立 Host 进程共享同一配置的上游 #111 问题不受这项单 Host 保护影响。

### 2026-10-12 · 必跑的真实 Host 数据持久性门禁

新版 CLI 分类导出必须指定全新的 Host 机器绝对 .json 文件路径；旧的冷启动真实测试曾仍使用无路径导出，复核中已明确报错，不能混同为真实数据丢失。现已纠正测试，真实 DSH 0.1.2 的两 Session 三类别 cold restart/删除/文件导出和五个顺序 OS 进程场景合计通过 2 项。执行 npm run check:dsh-host-archives 时必须设置真实 AGENT_PICKET_DSH_HOST；缺 SDK 不再“全部跳过即成功”。三条 #111 双独立 Host 并发已知失败情况仍需另行手动运行、继续 NO-GO。
