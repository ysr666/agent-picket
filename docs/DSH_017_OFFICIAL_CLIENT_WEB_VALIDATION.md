# DSH 0.1.7 official Web union compatibility — independent release gates

Date: 2026-10-10. **Draft #58 candidate only.** Work was performed exclusively with isolated Mac clones, disposable DSH profiles and locally packed private npm tarballs. No normal user DSH settings/profile, main branch or real Agent task admission were changed.

## What is now proven

1. **Package-root entry is required for Client discovery:** DSH 0.1.7's `dsh-client-modules` recognizes a package-root Loader specifier such as `agent-picket`, not a subpath like `agent-picket/dsh` for client discovery. Our Bundle now inserts `agent-picket` and the package root exports the DSH Host entry. The host-neutral library remains at `agent-picket/core`. This is a **pre-release root export behavior change** requiring review by any consumer using `import ... from 'agent-picket'` directly.
2. **Use official Host and browser services only:** Host 0.1.7 settings remain owned by the `Config`/SettingsForms service introduced in #57. The 0.1.7 browser uses `ctx.configForms.describe()`'s official shared Host mirror and `ctx.remote.settings.mutate` for revision-fenced authenticated writes. In Cordis, the Client injection MUST declare both `remote` and `remote.settings`; omitting `remote` raises `cannot get property "remote" without inject` and prevents the UI contribution. Old 0.1.2 uses `settingsScope.bind`. Only one UI route can register per Client; **both versions rely on their existing single Host-owned consent**, never a second store or new custom RPC.
3. **Strict consent/ledger boundaries:** New Client adapter accepts only `agent-picket` settings, only localhost Host mode, and explicitly recognized `welcomeDecision`. Readback of malformed/future ledger fails closed. It validates bounded canonical fictional ledger before write, carries the Host revision, serializes writes, accepts only the official result `ok:true`, folds it into DSH's shared Host mirror, and demands matching readback. Unsupported flags such as `autoBlockEnabled` are never written. The Host Config still validates the same ledger; no raw prompts, tool args or raw Session IDs are saved.
4. **Real isolated DSH 0.1.7-rc.2 Web/rights regression:** `tests/dsh-rights-browser.real.test.ts` **1/1 PASS** (source test runner, but *actual Host loads the officially npm-packed/installed plugin* through a disposable `dsh plugin --profile web add <local .tgz>`). This exercises first-run consent, Host persistent choices, union reflow/AX/focus/forced-colors and negotiation interactions, not merely a static button. The test switches to the official installed Profile only when `PICKET_TEST_017_HOME` is explicitly set. Actual Windows NVDA/OS high contrast/native browser zoom 200–400% are not tested.
5. **Real DSH 0.1.2-rc.1 regression:** **5/5 PASS** in the same source checkout for native Host SettingsFile+CommandRuntime, real Chrome Web consent from both source and offline-installed package, and Composer → sidebar parity from both source and package. No regression to the old native implementation was seen.
6. **Typecheck, build and normal tests:** **212 tests / 189 pass / 0 fail / 23 conditional skips** before submission. Six new always-on tests cover 0.1.7 default OFF, Host CAS acceptance, refusal, unsafe ledger/unknown-field gating, nonloopback denial and hostile readback; old tests remain. `npm pack --ignore-scripts --dry-run` confirms the new browser asset/Bundle in the package.

## Remaining release blockers — do not suppress or overstate

- **0.1.7 typed Composer → Host `/union` parity remains NOT VERIFIED.** The old `tests/dsh-union-composer-sidebar.real.test.ts` assumed a legacy `/api/commands/execute` fetch response; the 0.1.7 official command client calls `ctx.remote.commands.execute(session.sessionId, line, attachments)` and the legacy response waiter timed out. Even after adjusting the test to allow either `/api/commands/execute` or `/api/commands.execute` on the local Host, no matching response was observed within 8 seconds. This might reflect an actual client command issue, a different official transport, or a changed Composer interaction; no conclusion of parity is justified. A newer test must observe the actual official command lifecycle or Host events **without** private RPC and verify real typed command behavior.
- DSH 0.1.7 native Host SettingsForms schema transform/canonical ledger validation needs a **real isolated Host mutate rejection test** (mocked unit tests and exported JSON Schema are insufficient). The `--dump-config-schema` tool explicitly warns that the native ledger validation callback does not project into generic JSON Schema. Maintain strict native security validation and verify rejection before release.
- Cross-tab settings state synchronization, complete Host restart persistence and real typed `/union` commands on 0.1.7 are not all independently green.
- VoiceOver/NVDA with humans, real browser zoom 200/400%, physical OS high-contrast and full stacked-PR review remain required. Do not claim WCAG certification from automated Chrome AX/forced-color simulation.
- Root package-export change from core to Host entry is deliberately marked **breaking before first release**. Audit consumers before merging. The library's supported stable core entry is `agent-picket/core`.

**No main merge, npm publish, real blocking, external telemetry, alternate browser store, insecure permission bypass, or user profile modifications occurred.**
