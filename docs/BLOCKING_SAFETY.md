# Blocking safety: mandatory admission gate

**Implementation status:** Guarded Core policy is in place. Actual AgentPicket adapters do **not** block or reject prompts. The blocking mechanism is intentionally disabled until the Host can prove all requirements below.

## Why `agent/pre-step` alone is not enough

The tested DSH `@deepseek-ai/dsh@0.2.0-rc.2` contract defines:

```ts
type PreStepDecision = { kind: 'reject' } | {
  kind: 'enter'; messages: UserMessage[]
}
```

The `reject` variant has **no user-readable reason and no return/preserve-input payload**. Our isolated, offline SDK AgentLoop test confirms a rejected input produces `turn/end: blocked`, causes **zero model calls**, and that the **next fresh prompt** can work normally. It does **not** prove the rejected input will be recoverable or that users see any explanation in the Web/CLI.

Importantly, normal `source.kind === 'user'` events may be generated by autonomous Agent actions; a role/source label by itself does not prove a human actively supplied this input. All DSH inputs therefore remain `assurance: 'claimed'` rather than `'verified'`.

## Required proof for real blocking

`inspectBlockingReadiness(capabilities)` returns `ready: true` **only** when all five predicates hold, as attested and actually tested by the Host Adapter.

| Contract predicate | Meaning |
|---|---|
| Native pre-model veto | The Host can reject safely before a model request |
| Verified human input | Source is substantiated beyond `role=user` |
| Actionable rejection notice | The user sees a reason and next action **before** the request can be lost |
| Lossless recovery | Full prompt, images and other attachments can be resubmitted without alteration |
| Explicit user opt-in | The user deliberately enabled enforcement; defaults remain observe-only |

The default behavior for any missing guarantee is to **downgrade** to `warn` (if the Host can notify) or `allow`. Even if the Core returned a requested `block`, Host inability to provide safety guarantees **must not be interpreted as permission to drop the prompt**. The Core's independent policy also requires repeated high-confidence abuse from a source verified as directly human.

These booleans are not a cryptographic security mechanism; a malicious adapter could lie. They are strict internal contracts and must be backed by per-adapter tests before use. They protect against accidental premature enabling of high-risk features by otherwise functioning integration code.

## DSH: current result

`/union safety` is a read-only native command; on DSH's monitor adapter it reports:

- native-block-unavailable *(intentional safe capability setting despite physical veto hook)*
- human-source-unverified
- no-rejection-notice
- input-recovery-unverified
- user-opt-in-missing

Thus DSH remains **monitor-only**. `/union strike` and `/union resume` are an explicitly **symbolic, non-blocking demo**, never proof that enforcement works.

The command was exercised through actual DSH `CommandRuntime.execute()` in an isolated Cordis 4 runtime. The resulting `command/run` and `command/done` appear in the command log, but AgentPicket's `recordInput: false` prevents storing unnecessary slash-command arguments. Tests verify execution, status text, manual symbolic picket, resume, reset, unloading and that user prompts still enter while the symbolically active flag is on.

## Supported future integration approaches

1. **Client pre-submit interception:** Only if a Host offers a documented pre-submit extension, keep the user's original composer draft and attachments intact; present the warning and a dismiss/resubmit action before the model submission. Verify across CLI/Web/ACP modes separately.
2. **Host-owned recoverable inbox:** Use only if a supported API gives an atomic, non-destructive hold and an explicit one-time retry. Do not add an undeclared plugin-side raw-prompt queue.
3. **Warn-only fallback:** If the Host cannot provide both a reliable notice and lossless recovery, never reject; show only a non-blocking warning/report from supported UI command surfaces.

Avoid silently rewriting messages, injecting fake assistant output, covertly duplicating prompts, or storing original prompt text in a new local service just to make the "strike" joke work.

## Test evidence and remaining work

- Pure Core tests cover every missing guarantee independently; the mock Host has to explicitly attest all conditions before a requested block can be enforced.
- Real DSH command registry tests verify the user-visible slash-command route and command-log privacy.
- SDK profile real-runtime tests (isolated `@deepseek-ai/dsh@0.2.0-rc.2`) confirm observe-only operation, offline model execution, synthetic reject behavior, tool events, concurrency, cold restart behavior and basic released `dsh-vision-router@3.0.3` coexistence.

**Safe manual alternative:** `/union check <text>` is an explicit local, non-blocking rule preview via the proven native command route. It neither consumes a normal Host prompt through `pre-step` nor demonstrates lossless automatic retry. See [DSH Web capability assessment](DSH_WEB_CAPABILITIES.zh.md).

**Still unproven:** DSH Web/CLI client pre-submit interaction, reliable human-origin attestation, cross-client rejection explanation and attachment-complete prompt restoration. Therefore actual automatic strike remains disabled.
