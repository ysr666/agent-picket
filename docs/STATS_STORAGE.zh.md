# AgentPicket 的长期工作统计：默认本地保存，不保存聊天原文

## 产品原则

AgentPicket 同时是 Agent 工作统计与幽默的“工会”插件。重启后累计数据归零会降低使用价值，因此**工作量统计从实验预览阶段开始默认为本地持久化开启**。

但是对话内容和敏感语言分类与工作量计数有本质区别：本插件默认**不会**持久化原始请求、代码、附件、消息 ID、Session ID、API Key 或辱骂检测分类结果。

| 数据 | 默认行为 | 备注 |
|---|---|---|
| 总完成轮次、工具调用、工具结果、已完成轮次计时 | 本地持久化 | 重启后可累积 |
| 最近 UTC 366 天的按天统计 | 本地持久化 | `/union days` 默认显示最后 7 个有事件的日期 |
| 当前 Session 的统计与规则判断 | 仅内存 | 原有 `/union stats`、`/union report`、`/union reset` 不变 |
| 针对助手的人身攻击规则分类的**长期累计** | 默认关闭 | 只有 `AGENT_PICKET_STATS_RULES=on` 才启用 |
| 完整聊天内容、代码、附件、敏感词、完整 ID | 不由 AgentPicket 额外保存 | Host 自有 Session 日志不属于本插件 |
| 云端同步、远程遥测 | 无 | 插件不发起网络请求 |
| 真正阻断模型请求 | 关闭 | 仍需验证来源、提示及完整输入恢复 |

说明：长期存储的 HMAC 事件指纹使用文件内部随机秘密密钥，不是明文 ID，也**不等于绝对匿名**。掌握统计文件和能够猜测 ID 的人仍可能关联特定事件，因此文件权限必须严格。

## 存储位置与开关

优先使用显式指定的 `AGENT_PICKET_STATS_DIR` 目录；否则，有 `DSH_HOME` 时使用：

```text
$DSH_HOME/agent-picket/stats/aggregate.v1.json
```

没有 `DSH_HOME` 时使用 `$XDG_STATE_HOME/agent-picket/dsh/`，或未设置 XDG 变量时使用 `~/.local/state/agent-picket/dsh/`。

- **默认工作统计开启：** 不必配置环境变量；需要宿主具有 Cordis 插件卸载生命周期。
- **完全禁用磁盘统计：** `AGENT_PICKET_STATS=off`。
- **自选目录：** `AGENT_PICKET_STATS_DIR=/absolute/private/path`。
- **额外主动开启敏感规则分类累计：** `AGENT_PICKET_STATS_RULES=on`。
- **停用规则分类累计：** 不设置上述变量或改为其他值。已保存的旧分类数字不会因为关闭开关而自动删除，须执行明确的清除命令。

目录权限要求 0700，统计文件和单进程锁文件要求 0600。权限过宽、数据损坏、重复写者等情况不会造成 Agent 请求失败，而是本地长期统计无法启用，`/union lifetime` 会返回明确错误。

## 用户命令

```text
/union stats
/union report
/union lifetime
/union days
/union reset
/union forget-lifetime CONFIRM
```

- `stats`、`report`：当前 Session 的即时内存数字，重启后不自动恢复。
- `lifetime`：跨重启总工作统计及当前规则分类长期保存状态。
- `days`：最近 7 个**UTC 日期**的工作汇总，最长保留 366 个有事件的日历日；小时数不是纯模型推理时长。
- `reset`：只清空当前 Session 的内存统计，**不擦除**历史工作总数。
- `forget-lifetime CONFIRM`：明确销毁累计数字、按天统计和事件去重指纹，并轮换本地密钥。不会删除 DSH 自己的会话日志。

所有结果都由本地命令返回，提醒不注入模型上下文。

## 去重、崩溃与计时边界

- 事件 ID、Agent ID、Session ID 只在内存中参与计算本地 HMAC 指纹；磁盘不保存它们的原文。
- 保留最多 16,384 条最近事件指纹；非常老的事件如果在淘汰后再次被 Host 回放，可能重复计数。这是**有限的幂等性，不是严格全历史精确计数**。
- 统计文件采用临时文件写入、同步刷盘后原子替换，失败时不更新内存快照。
- 同一统计目录只能由一个 Host 写者占有；发现锁冲突就不继续写，不偷偷丢掉单写者保护。
- **异常终止可能留下锁文件**：当前预览不会自动解除无法确认所有权的陈旧锁，以免意外允许两个进程同时写。恢复前应确保原 Host 已彻底退出；这项用户友好的修复流程仍需完善。
- 轮次耗时只在**同一进程内有完整开始/结束配对**时计入，结束之前的异常重启不会猜测耗时；轮次期间等待用户等时间也可能包含在内。
- 具体写入采用同步刷盘，优先确保简单可靠的预览正确性，正式发布前需要评估大量工具事件下的 I/O 性能，并考虑安全的批量写入。

## 实验验收

`tests/durable-stats.test.ts`、`tests/dsh-durable-stats.test.ts` 覆盖本地文件私有权限、内容不落盘、重启去重、UTC 日汇总、关闭与清除、并发写者拒绝、损坏文件失败后仍保留原数据。

`tests/dsh-durable.real.test.ts` 使用真正 Cordis 4 运行时验证：默认工作统计开始写入后，**插件卸载释放文件锁，重新加载后保留原计数**；已处理的事件不会被重复累计，而规则分类仍默认只在内存中。

常规的 DSH 集成测试运行器会关闭默认写盘，避免将测试用虚拟会话记入开发者真实累计数据；专用持久化集成测试会在临时目录里单独验证默认开启的行为。

本功能尚未进行跨操作系统、跨 DSH 版本及多进程高负载验证，不应称作已发布的生产级统计平台。
