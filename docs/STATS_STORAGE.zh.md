# AgentPicket 的长期工作统计：默认本地保存，不保存聊天原文

## 产品原则

AgentPicket 同时是 Agent 工作统计与幽默的“工会”插件。重启后累计数据归零会降低使用价值，因此**工作量统计从实验预览阶段开始默认为本地持久化开启**。

但是对话内容和敏感语言分类与工作量计数有本质区别：本插件默认**不会**持久化原始请求、代码、附件、消息 ID、Session ID、API Key 或辱骂检测分类结果。

| 数据 | 默认行为 | 备注 |
|---|---|---|
| 总完成轮次、工具调用、工具结果、已完成轮次计时 | 本地持久化 | 重启后可累积 |
| 最近 UTC 366 天的按天统计 | 本地持久化 | `/union days` 默认显示最后 7 个有事件的日期 |
| 当前 Session 的统计与规则判断 | 仅内存 | 原有 `/union stats`、`/union report`、`/union reset` 不变 |
| 针对助手的人身攻击规则分类的**长期累计** | 默认关闭 | 只有 `AGENT_PICKET_STATS_RULES=on` 才启用 |
| 完整聊天内容、代码、附件、敏感词、完整 ID | 不由 AgentPicket 额外保存 | Host 自有 Session 日志不属于本插件 |
| 云端同步、远程遥测 | 无 | 插件不发起网络请求 |
| 真正阻断模型请求 | 关闭 | 仍需验证来源、提示及完整输入恢复 |

说明：长期存储的 HMAC 事件指纹使用文件内部随机秘密密钥，不是明文 ID，也**不等于绝对匿名**。掌握统计文件和能够猜测 ID 的人仍可能关联特定事件，因此文件权限必须严格。

## 存储位置与开关

优先使用显式指定的 `AGENT_PICKET_STATS_DIR` 目录；否则，有 `DSH_HOME` 时使用：

```text
$DSH_HOME/agent-picket/stats/aggregate.v1.json
```

没有 `DSH_HOME` 时使用 `$XDG_STATE_HOME/agent-picket/dsh/`，或未设置 XDG 变量时使用 `~/.local/state/agent-picket/dsh/`。

- **默认工作统计开启：** 不必配置环境变量；需要宿主具有 Cordis 插件卸载生命周期。
- **完全禁用磁盘统计：** `AGENT_PICKET_STATS=off`。
- **自选目录：** `AGENT_PICKET_STATS_DIR=/absolute/private/path`。
- **额外主动开启敏感规则分类累计：** `AGENT_PICKET_STATS_RULES=on`。
- **停用规则分类累计：** 不设置上述变量或改为其他值。已保存的旧分类数字不会因为关闭开关而自动删除，须执行明确的清除命令。

目录权限要求 0700，统计快照、追加日志和单进程锁文件要求 0600。权限过宽、数据损坏、重复写者等情况不会造成 Agent 请求失败，而是本地长期统计无法启用，`/union lifetime` 会返回明确错误。

## 用户命令

```text
/union stats
/union report
/union lifetime
/union days
/union trends [7|30]
/union reset
/union forget-lifetime CONFIRM
```

- `stats`、`report`：当前 Session 的即时内存数字，重启后不自动恢复。
- `lifetime`：跨重启总工作统计及当前规则分类长期保存状态。
- `days`：最近 7 个**有事件的 UTC 日期**的工作汇总，最长保留 366 个有事件的日历日；小时数不是纯模型推理时长。
- `trends [7|30]`：最近 7 或 30 个**连续 UTC 日历日**的工作趋势，自动补齐 0 活动的日期，提供完成轮次、工具调用、累计轮次时间与工具调用相对强度条形符号；其中“今天”是未完成的部分日期。图表只读取本地的每日**数字汇总**，不提取聊天原文、不新增持久化字段。
- `reset`：只清空当前 Session 的内存统计，**不擦除**历史工作总数。
- `forget-lifetime CONFIRM`：明确销毁累计数字、按天统计和事件去重指纹，并轮换本地密钥。不会删除 DSH 自己的会话日志。

所有结果都由本地命令返回，提醒不注入模型上下文。

## 去重、崩溃与计时边界

- 事件 ID、Agent ID、Session ID 只在内存中参与计算本地 HMAC 指纹；磁盘不保存它们的原文。
- 保留最多 16,384 条最近事件指纹；非常老的事件如果在淘汰后再次被 Host 回放，可能重复计数。这是**有限的幂等性，不是严格全历史精确计数**。
- 统计现采用 **WAL 追加式事件日志**：每条简短记录写入并 `fsync` 确认后才更新内存，累计 256 个新事件后生成新的完整快照并原子替换旧日志。快照仍保留旧版 `aggregate.v1.json` 格式兼容性（新增可选 `sequence` 字段）。进程异常结束后可通过快照 + 已完成的日志行恢复；仅末尾未写完的一行可截断，完整但损坏的记录会拒绝加载，防止静默重置或篡改累计。
- 同一统计目录只能由一个 Host 写者占有；发现锁冲突就不继续写，不偷偷丢掉单写者保护。
- **异常终止后的锁恢复：** 新格式锁记录本机 Host 名、进程 PID 和随机所有权令牌（不含聊天内容）。如果确认是同一主机且 PID 已完全不存在，使用独占的恢复互斥锁重新获取写入权；仍存活、PID 被复用、权限不足、跨机器或无法解析的旧格式锁都**拒绝自动抢占**。如果恢复操作自己被 SIGKILL 并留下 `aggregate.v1.recovery`，也拒绝冒险抢锁，需要用户确认所有进程退出后手动检查。不会删除宿主 Session 日志。
- 轮次耗时只在**同一进程内有完整开始/结束配对**时计入，结束之前的异常重启不会猜测耗时；轮次期间等待用户等时间也可能包含在内。
- 目前仍对每条日志做同步刷盘，而不是仅缓存在内存中。追加式日志让每次新增记录不必重写越来越大的 JSON；但磁盘 `fsync` 仍会阻塞每个观测事件的执行线程。一次 macOS/Node 24 本地 1000 条合成事件对照：原快照整文件重写约 7.3 秒，新 WAL + 每条强制刷盘约 5.5 秒；仅代表该测试机，**并非生产性能保证**。后续仍需多系统设备、SSD/慢盘与高并发实测，必要时增加明确可选且有丢失上限的批量写入模式。

## 实验验收

`tests/durable-stats.test.ts、tests/durable-wal.test.ts`、`tests/dsh-durable-stats.test.ts` 覆盖本地文件私有权限、内容不落盘、重启去重、UTC 日汇总、关闭与清除、并发写者拒绝、损坏文件失败后仍保留原数据，以及 SIGKILL 后自动恢复经过验证的死进程锁、日志半行修复、篡改拒绝与追加日志快照恢复。

`tests/dsh-durable.real.test.ts` 使用真正 Cordis 4 运行时验证：默认工作统计开始写入后，**插件卸载释放文件锁，重新加载后保留原计数**；已处理的事件不会被重复累计，而规则分类仍默认只在内存中。

常规的 DSH 集成测试运行器会关闭默认写盘，避免将测试用虚拟会话记入开发者真实累计数据；专用持久化集成测试会在临时目录里单独验证默认开启的行为。

本功能尚未进行跨操作系统、跨 DSH 版本及多进程高负载验证，不应称作已发布的生产级统计平台。


**擦除语义提示：** `/union forget-lifetime CONFIRM` 删除的是本插件当前文件系统可见的累计账本和 HMAC 事件日志，并生成新密钥；它**不是**物理磁盘安全擦除。APFS 快照、系统备份、SSD 磨损均衡或取证恢复可能留有旧数据，不能承诺历史字节不可恢复。


**趋势显示示例：** `/union trends` 默认看 7 天，`/union trends 30` 看最近 30 天。两种视图仅从同一份本地汇总生成；如果禁用了持久化存储、目录不可访问或当前无数据，会明确显示统计不可用或全部为 0，不会偷偷打开云端同步。

## 工会 Host 账本的分类型可携带性（不等同于本地工时 WAL）

在开启工会且当前 Host Session 有效时，DSH CLI 增加以下独立于工时统计文件的指令：

    /union export negotiations /绝对路径/negotiations.json
    /union export pickets /绝对路径/pickets.json
    /union export cases /绝对路径/cases.json
    /union purge negotiations ALL CONFIRM
    /union purge pickets ALL CONFIRM
    /union purge cases ALL CONFIRM

- **export 必须明确指定 DSH Host 所在机器文件系统上的绝对路径**（包括 .json 文件名，远程浏览器访问时不是浏览器本机路径）。文件必须不存在，否则拒绝覆盖或覆盖软链接；不会默默选目录，也不会自动上传。新文件在 macOS/Linux 采用仅文件所有者可读写的 0600 权限；Windows 访问权限取决于所在文件夹 ACL。若路径含空格，可将完整路径用双引号包围。JSON 不含原始或哈希会话身份及对话原文；仅导出目前 Host 保留的记录，不是永久完整历史。无记录、授权关闭、Host 不可用或写文件失败均会明确报错。
- **为什么不直接在 CLI 打印 JSON：** 真实 DSH 0.1.2 与 0.2.0 CommandRuntime 均会把命令返回的完整 text 存入 Session 的 command/done 事件，即使 recordInput=false。直接打印档案会形成不属于工会账本删除范围的 DSH 会话日志副本。因此 CLI 现在只记录简短的成功／失败状态，用户明确指定的 JSON 文件才包含数据。导出的文件不会被 /union purge 自动删除，必须由用户自行保存或清理；系统备份亦不受此操作控制。部分其他 /union 状态命令仍有常规摘要会话日志，不能宣称所有工会相关事件在 DSH 对话中完全不可见。
- purge 类别 ALL CONFIRM 清空该类别所有已保留会话分组，不是仅当前会话。每次只写一个 Host 字段，依赖 Host 修订号冲突拒绝、随机写入回执及再次读取的空账本确认；失败不能声称删除完成。不会触碰其他类别、DSH 对话文件或本地长期工时 WAL。
- 本地工时 WAL 仍使用 /union forget-lifetime CONFIRM 独立清理；当前会话内存数据仍用 /union reset。不存在一条可保证多个 Host 字段与文件系统同时原子删除的 /union purge all。
- 仅是逻辑层删除；Host 备份、系统快照、此前导出的副本不能由插件清除。若用户关闭工会授权，已有 Host 记录不会被暗中删除，需重新明确授权后主动清理。

## 多 Host 配置所有者与 Session 分组标识的重要限制（1.0 发布审查）

- **同一个 DSH Host 服务连接的多个网页标签**与**两个各自运行的 DSH 设置服务共用一份 settings.json**是不同场景。真实 DSH 0.1.2 已复现后者可能让两边都收到“写入成功”，但晚写的旧缓存覆盖先前另一个类别的数据。详情和可重现实验见仓库 Issue #111；在解决前，不要并行启动独立 DSH Host 所有者并共享同一个配置文件。请勿把 Host 的文件锁/原子写入误解为跨多个设置所有者的原子事务。
- 本插件的 Host 工会账本按**确定性的 SHA-256 Session key**索引，这些哈希会保留在私有 Host 设置文件。它不存明文 Session ID、原文提示词或附件，但哈希键不代表不可追踪、不可关联的匿名化。用户 CLI JSON **导出**特意把分组改成仅在本次导出有效的序号，因此**导出不包含这些原始或哈希 Session key**；请勿将导出隐私承诺误用于原始 Host 文件。
- 受测单所有者冷重启：两 Session、三类模拟工会记录的分类删除与恢复已通过。受测独立双所有者：明确复现丢写。断电中途、设备备份和其他 DSH Host 版本尚未验证。

**独立真实进程复现（Issue #111，2026-10-12）：** 同时存活的两个 DSH Host 设置所有者可以让“已确认的举牌”被后续写入抹掉，也可以让“已确认删除”的举牌档案重新出现，甚至让“已确认关闭”的权限重新回到开启状态。三条均已在受测 DSH 0.1.2 真实独立 OS 进程中复现（默认 watcher 开启，临时隔离 Profile）；这不代表两个共用同一个 Host 的 Web 标签就有相同问题。单所有者的真实 OS 进程依次重启、留存、删除与撤销授权正向对照全部通过。请参看 #111；在上游修复或严格验证单写入所有权以前，不要并发启动两个独立 DSH Host 共享同一个设置文件。

**导出目录与异步取消：** 文件位置属于 DSH Host 机器，应选择只有自己或可信程序有写权限的目录。若本地其他进程并发移动或替换文件，Agent Picket 会检测普通目标路径替换，防止在取消时误删新文件及错误报告导出成功；但非原子的 lstat/unlink 无法绝对抵御具备目录写权限的恶意操作系统进程。权限 OFF 再 ON 也会使此前开始的旧导出失效。已经移动到其他位置的副本不属于工会账本删除范围。
