## 本地议题行动

- 工会主页增加「本地议事厅」，三条明确对应真实 GitHub Issue 的公开议题：#80 用户消息和附件无损恢复、#79 警告与申诉、#82 本地记录导出/删除。
- 用户主动选择议题会改变网页当前选中按钮、可复制的只读倡议文字和外部 Issue 链接。中英双语，明确不存储支持者人数、无模型自发投票、无任何 Host 工会写入、无自动联网上传/评论。
- 即使未开启工会模拟，倡议草稿和公开议题仍可阅读。只读文字框支持用户原生选择和复制，不主动请求剪贴板权限。该功能独立于工会模拟授权、实际任务拦截授权；不声称真人已经参与、加入工会或赞成议题。
- 该体验是*真正的用户发声准备工具*，不是已实现的真正跨-Agent 集体票决。#85 真实多 Agent 身份认证与表决仍待研究。

## #80 DSH 0.2 SDK「文本 + PNG」拒绝

- 在完全隔离的 `sdk-minimal` Profile 中显式插入官方 `@deepseek-ai/dsh-attachment-local`，存储根位于临时测试目录；整个过程使用离线模型替身，网络代理指向不可达本地端口。
- 由测试代码附送有效 16×16 PNG base64 图片与字符串 `BLOCK TEST`；官方 `session/prompt` 接口接收它们，真实 Host 的 `agent/inbox/spliced` 事件存在图片的 *attachment reference*，之后 `agent/pre-step` 在测试标记上返回 reject。
- 确认拒绝轮次仅产生 blocked 结局，不触发 `step/start`、`user/message` 或模型调用；下一条正常请求可以继续执行。
- 这**没有证明图片原字节能够从 Host 重新取回，也没有证明用户能自行重传原消息与附件**。一次 Host 设置或存储中的 attachment reference 不是自动恢复/重试 API。UI 显示完整本地草稿也不是阻断恢复。因此 #80 仍为 Open，真实任务阻断保持 OFF。
- 本回归 `tests/dsh-agentloop.real.test.ts` 只有在提供真实 DSH 0.2 Host 路径时运行，普通 `npm run check` 中条件 SKIP；不得把默认单测的绿灯当作真实附件安全认证。

## 阶段性门禁与未验收

- 需要具备已验证来源、真正的 pre-submit hold 或 Host 原子重试接口，并在 Web/CLI/SDK 端对正文及所有附件做到 byte-for-byte 的一次性无损恢复；同时有拒绝解释、暂停/恢复/绕过和完整的冲突/崩溃测试，才可讨论启用真实阻断。
- 新的议题区须接受人工键盘/VoiceOver/NVDA、暗色主题、400% 放大与真实用户理解测试。不能从自动 Chrome/AX 通过推导出真人无障碍签收。
