# Windows NTFS WAL 实际写入实验 · 2026-10-13

这是 Agent Picket 对真实 Windows 持久账本的下一步独立验证，但**绝不是已经具备生产安全保证的存储后端**。

`src/adapters/node/windows-ledger-writer.experimental.ts` 是刻意被 `package.json` 排除的研究模块，任何已安装的 DSH、Claude Code 或 Codex 插件都不能调用它。其 `ExperimentalNtfsWalWriter` 仅在 Windows 可实例化，使用既有 DurableStats v1 的 JSON 快照和逐行 HMAC-SHA256 WAL 结构，而不是创建不兼容的新账本。每个合成 tool-start 写入都要先确认受保护目录、受控文件清单和本进程锁身份，写入日志并 `fsync` 后才更新内存中的累计计数；恢复时通过 v1 只读重放模块确认签名、顺序和数据完整性，并恢复指纹去重集合。实验 API 只接收合成事件 ID，不用于拦截或记录用户对话。

安全范围严格受限：只自动创建全新、空的、受保护 NTFS 目录；现有旧锁、恢复锁、坏快照、受损 WAL、最后一条未完成日志均拒绝。只允许**没有未验证接管的正常 close→open**，不自动抢占死进程锁。没有实现 WAL checkpoint，硬性限制最多 255 条已确认记录；超过限制拒绝后续写入，避免无界日志增长或误称可生产使用。整个原型不进入 npm 包，不改变当前 `DurableStats` 在 Windows 上构造之前即拒绝的行为。

`tests/windows-ledger-writer.real.test.ts` 在真正的 Windows Runner 和临时私有 NTFS 目录上执行三个验收：

1. 新建真实账本、写两条带签名和 fsync 的记录、同 ID 去重、拒绝第二个同时取得锁的写入者；正常关闭后重新打开，确认序号/累计计数/去重不变，新增记录仍保持连续序号；通过独立 WAL 验证器复核，再验证完整日志记录被篡改时拒绝写入且保留坏日志原文。
2. 启动独立 Node 子进程，写入并 fsync 一条记录后强制终止进程；锁必须保留，下一写入者必须拒绝接管，但独立只读重放仍能验证已经确认的计数未丢失。
3. 在非 Windows 系统上，即使存在合法路径也不允许误启用该实验性 NTFS 写入器。

**仍需验收：** 一次性锁创建后文件句柄与 NTFS DACL 检查之间的 TOCTOU、跨进程死锁身份比较及原子删除、Windows 上已打开文件的 checkpoint/原子替换、真实完整 `DurableStats` 功能和所有被跳过的 Windows 测试、实际安装的各 Host×OS 兼容矩阵。任何已验证的“独立实验写入”都不等于“可以让工会真实罢工”；1.0 发布闸门继续 NO-GO。

## 2026-10-13 · 手动检查点与精确崩溃窗口实验

实验写入器新增**显式且仅用于测试**的 `checkpointForTest()`，不自动后台运行，也不进入 npm 包。它在受控锁和私有 ACL 验证后，将现有 v1 密钥、连续序号、累计次数、UTC 每日次数和最多 16384 个去重指纹写入新的快照临时文件并 `fsync`，验证 NTFS 文件 ACL 后以原子重命名提交快照。然后新建并同步空的 WAL 临时文件，**先关闭原 WAL 文件句柄**，再替换旧 WAL，验证目标权限并重新打开追加句柄。

在快照提交与旧 WAL 替换之间若进程崩溃，**旧 WAL 必须保留**；独立 v1 只读重放器应按快照序号跳过已确认旧记录，不重复累计工时。异常终止产生的旧锁也必须保留，实验原型不能自动抢锁。手动检查点后的干净关闭与重开，必须同时保持总次数、逐日次数、去重指纹和连续序号。已添加两项独立的 Windows 专项 E2E：正常检查点→新 WAL→重新打开→去重→再次检查点，以及子进程在快照 `fsync`/重命名后通过精确测试回调停住、父进程强制终止并验证旧 WAL 完整保留和零重复重放。

此原型依然 **不是生产 Windows DurableStats**：检查点需要测试 API 手动触发，每段 WAL 最多 255 条，指纹集合最多 16384 项；NTFS 检查与真实文件句柄之间仍有 TOCTOU，安全的死锁接管、强制断电及 DSH/Codex/Claude 正式适配仍未验收。Windows 正式统计功能继续在 `mkdirSync` 之前拒绝启用，1.0 发布闸门必须保持 NO-GO。

## 2026-10-13 · 文件句柄身份复核（仍非原子安全证明）

新增只在 Windows 有效的实验辅助函数 `verifyNtfsOpenFileIdentity(fd, path)`：同时读取 `fstat` 与 `lstat` 的真实文件类型、设备 ID、NTFS inode/file-index 以及硬链接数；若不支持文件 ID、路径被替换、路径不存在、链接数量异常或任一调用失败，统一 **fail closed**。实验写入器在初次打开 WAL、每次追加事件、创建检查点前以及检查点替换 WAL 后都会检查已打开句柄是否仍对应经过检查的路径。新增真实 Windows 专项测试，验证正确打开的文件获识别，而将相同句柄与另一文件或不存在的路径比较会被拒绝。

注意：两次系统调用之间仍存在竞争窗口；这只是削弱了“检查 A 文件、写入 B 文件”的风险，不是锁定内核对象与 ACL 的不可分割事务。实际安全上线还需要 Windows handle-based 防重解析检查、DACL 与句柄对象绑定、完整锁接管序列及多进程压力测试；所有实验模块继续排除在发行包外。

## 2026-10-13 · 独立双进程抢锁回归

先前原型已验证同一 Node 进程中的第二个写入对象无法夺锁。新增一项真正的**两个 OS 进程**验收：父进程持有已 fsync 的私有 NTFS WAL，另起一个 Node 子进程尝试构造同路径的实验写入器。子进程必须明确返回“第二写入器拒绝”，且退出码为 0；它不能修改锁或日志。父进程随后还能追加并确认两条记录，正常关闭后独立只读恢复必须显示连续序号 2、累计工具调用 2。此项仍属于源代码/隔离实验，不代表正式多 Host 同步、跨进程死锁恢复或 Windows DurableStats 安全支持。
