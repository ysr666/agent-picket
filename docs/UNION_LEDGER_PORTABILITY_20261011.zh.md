# Agent Picket · 全会话模拟协商及象征性纠察账本导出/清除（2026-10-11）

> Draft · Issue #82 的后续增量。在 Union HQ 的「工会记录自主权」中，用户独立操作**已经在当前 Host 官方 Agent Picket settings 中保存的两种结构化账本**，不是 DSH 对话/工作记录的全量备份或 Agent 的实际劳动关系记录。

## 用户操作

当明确授权工会模拟后，若某类账本当前包含已保存会话，界面独立列出：
- 「模拟协商、请愿与协议记录」：来自老版本 `unionLedger`（至多 8 组），包含仅数值/枚举的协商协议、未处理请愿、结案历史、验证过的工作时长游标；绝不包含原始聊天、文件或独立真实工时总账。
- 「象征性举牌与纠察行动记录」：来自 `unionPicketLedger`（至多 8 组，每组至多 12 件），包含当前是否举牌与历史 raise/lower 事件。真实 Agent 工作永远不阻断。

两类账本各有独立「导出此完整账本（JSON）」按钮，分别下载 `agent-picket-negotiations.json`、`agent-picket-symbolic-pickets.json`。同一文件中不同会话按 `group:1,2,...` 以及仅当前会话的 `current:boolean` 标注。文件不出现原 Session ID、SHA-256 Session 键、Host 的随机写入令牌、Agent 消息/文件内容。浏览器本地 Blob 生成文件，没有额外外部 API / 上传行为。

每类账本也有独立「清除此完整账本……」及第二步「确认永久清除此账本」。第一次点击只显示警示，第二次才调用已授权 Host 的设置写入。**仅清除对应的一个字段**，不触碰其他协商/纠察/模拟案件字段。撤销授权只是隐藏，不自动擦除；新用户交互日后仍可能新建账本。

## 安全及兼容

- 保留官方已部署 v1 字段、schema、严格解析和最大字节限制，不新增自定义 Host API，不改变旧版 `unionLedger` 协议，不额外持久化原文/标识。
- Host 读取 `ready+host+writable`、用户授权和已绑定匿名会话；对某一账本的双击删除，确认点击时与实际执行时必须满足准确会话键、该账本的已保存分组数/事件数/随机写入回执均一致。任何变化都要用户重新确认。
- 通过已有官方 `settingsScope.set()` 修订号 CAS 写入 `{schemaVersion:1,sessions:{},writeToken:<new random 128-bit>}`。写后重读全部会话键确实为 0，且新回执匹配才认为清除成功；拒写/静默丢写/授权撤销/会话切换均失败。
- 原始 `unionDignityCases` 案件簿、Host 的累计工时 RPC、底层 DSH 对话/附件、其他副本/备份都不清除。工作量大于阈值或用户主动新举牌，之后仍可能产生新记录。导出不是完整历史：这两套账本各最多保留八个匿名会话分组，旧组可能被淘汰。
- 文件采用严格 allowlist 后序列化：协商导出仅 v1 State 的数值/枚举字段；纠察导出只保存布尔状态及枚举事件。每个导出文件的分组序号不是可用于反向索引 DSH 会话的持久映射。

## 测试覆盖

- 两会话 Host Fixture：分别生成协商、纠察、模拟案件；两类实际 JSON 结构检查与没有标识字段；错误会话、错误分组数、错误事件数、写入回执不匹配、拒写与静默丢写；先删除协商后验证纠察未变，再独立删除纠察，案件仍存；切换会话及重建实例数据依然一致；授权 OFF 不允许读取、导出或改写。
- 真正 DSH0.2 Chrome：从真实普通用户消息自动检测，到同一会话的模拟案件流程与独立导出/清除，在最末尾实际下载两份结构化账本，双击分别擦除，通过官方鉴权 `settings/describe` 确认协商、纠察和案件三套 Host 保存分组各自为零，授权仍开启。
- DSH0.1 Chrome 回归；npm 严格 <=250000 字节；GitHub CI 多系统通过后才称完成。该取证文件保存在 GitHub，不打入 npm 用户包。

## 仍需继续

Issue #82：插件 Node 层 `DurableStats` 有单独本地加密/键控摘要文件及 `reset()` 能力；DSH 0.2 的 Lifetime Work RPC 是另一套仅可读的 Host 工作统计，**不等于插件设置里的协商游标**。没有完整安全、用户已授权、可追溯的浏览器删除 API，不得谎称这次操作擦除了工时统计/本地文件或原始对话。需要分别研究各版本的真正用户可操作出口，并给出明确权限和数据保留范围。#83 检测误报与 #80 所有文件附件无损恢复仍是实际任务拒绝的绝对门禁，保持 observe-only。
