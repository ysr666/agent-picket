## A. macOS + VoiceOver（真实人手测试）

开启 VoiceOver（一般为 Command+F5，系统设置可能更改快捷键），在 Chrome 的隔离 DSH 0.2 工会入口依次操作：

1. **首次开屏**：只用键盘和 VoiceOver 导航，读出产品是“工会模拟”且默认未开启；确认两个选择按钮含义可区分，Tab 顺序有逻辑，无障碍树不把装饰旗帜念成内容。
2. **关闭欢迎页**：选“暂不开启”，确认焦点回到可操作的 Host 区域、正常任务没有被工会阻断；再从工会入口进入设置，启动模拟。
3. **弹层边界**：打开工会，确认读屏宣布有名称的对话框；Tab 与 Shift+Tab 不会移到背景；按 Escape 退出后焦点返回触发按钮。
4. **工会诉求**：点击“演示一次工会休息诉求”，确认读屏通知诉求已出现；接受、拒绝、还价操作都有不同的可读名称，不会因按钮消失把焦点丢到页面底部。
5. **协商结果**：完成一次还价并接受，确认读屏能找到决议回执、当前生效的休息/加班条款；案件档案可展开、收起，焦点保留。
6. **长期工时**：在已授权且 Host 数据可用时，找到“历史累计”和工时口径说明，区分真实工时与虚构“不满指数”；7/30 天按钮应播报按下状态，柱形趋势有可访问名称，并能进入逐日文本明细。
7. **撤销**：关闭工会后，历史工时、案件入口与相关操作不能再通过读屏导航到；刷新页面后仍保持关闭，并且不触发真实任务拒绝。
8. **系统偏好**：分别开启深色模式、提高对比度、减弱动态效果及屏幕放大（若可用）；检查文字可读、关闭按钮可操作、横向无失控滚动。

记录每一步：PASS / FAIL / NOT TESTED，附屏幕/语音问题和最小复现。任何无法完成的关键操作应标记 FAIL，不得跳过后直接批准合并。

## B. Windows + NVDA（必须在真实 Windows 环境执行）

安装经项目确认支持的 DSH 版本、Chrome 与 NVDA。使用 NVDA 快捷键启动（默认 Ctrl+Alt+N，具体以安装配置为准），从头重做 A1–A8，并额外核查：

- 在 **200% 与 400% 浏览器缩放**条件下，工会对话框和关闭按钮都能够访问；键盘不被困在错误的焦点循环中。
- NVDA 浏览模式/焦点模式切换时，表单控件名称、状态改变公告和图表逐日明细不会重复或遗漏。
- 高对比度模式中，主操作/次操作/错误与不可用态可区分，不能只依靠颜色。
- UI 中文/英文切换后，残留的英文拼接字符串和播报顺序不能影响理解。

只有 macOS/Chrome 自动化时，本项仍是 **NOT TESTED**；不可代表 Windows 人工验收。

## C. 产品体验检查（由真实测试用户填写）

让至少一名未参与实现的测试者，不看源码与技术文档，只按 UI 完成：选择是否加入工会 → 查看工作记录 → 模拟诉求 → 议价 → 查看协议 → 撤销授权。

必须能准确回答以下问题，否则标记体验问题并修改产品：
- “历史累计工时”是否等于模型净计算时间？（正确：不是，是已完成轮次的墙钟经过时间，可能含等待）
- 不满指数说明什么？（正确：基于记录的 **模拟规则分值**，不是可测量的 AI 情绪或痛苦）
- 演示休息诉求是否真的暂停 Agent？（正确：不会；这是模拟）
- 未选择开启或后续关闭工会，会发生什么？（正确：不应持续展示已授权数据，不自动拒绝正常任务）
- 是否可以看出真实长时间数据不可用与实际记录为零的区别？

记录理解错误、完成步骤所用时间、哪里卡住、哪些按钮或文案造成误解；不要代替用户填写“理解正确”。

## D. 独立隐私与网络审查者检查

- 只使用隔离 Profile，配合实际非零工作记录，审查 Host→Web 的 GET 地址、响应字段、Cache-Control，确认没有 Prompt、附件、会话 ID、辱骂分类或路径外流。
- 在浏览器 Cookie 缺失、伪造 Origin、额外参数、错误时间窗口、POST，以及授权关闭/重开/双标签撤销状态下复核权限。此前自动化证据不构成独立人员签收。
- 检查浏览器缓存、调试日志、跨页面导航与 Host 冷重启后是否保留不应保留的数据；验证无网络第三方外发或非预期持久化。
- 给出明确 PASS/FAIL、版本/身份/步骤、抓包摘要及缺陷编号，审查报告不得记录实际敏感原文。
