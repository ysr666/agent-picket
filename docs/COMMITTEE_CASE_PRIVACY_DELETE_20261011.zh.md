# Agent Picket · 工会案件隐私与本会话永久删除（2026-10-11）

> Draft #105。严格限制为模拟工会的 **`unionDignityCases`** 记录；不声称删除 DSH 原始会话日志、其他工会账本或其他会话。

## 用户体验

当授权状态为 ON，且当前会话有已立案的工会案件时，尊严委员会显示「删除本会话的工会案件记录……」。第一次点击后，按钮变为「确认永久删除本会话案件」，同时出现明确警示，说明不可撤销、与原对话及工时/纠察牌无关。再次点击才会发起官方 Host 设置写入；关闭弹窗、切换会话或撤销授权不会自动删除，也不会把上一会话已经进入确认阶段的按钮误用于新会话。

关闭 AI 工会只会隐藏模拟案件，**不等于删除历史**。重新开启后，原有案件仍会显示，直到用户明确执行本会话删除。此设计不把默认清除强加给用户，也不假装数据已经被删除。

## Host 安全机制

- 严格校验当前真实 `settingsScope`：用户必须授权、Host 可写、真实 Session 的 SHA-256 键必须与点击确认时的键完全一致。
- 使用唯一 128 bit 随机回执和官方 Host revision-CAS 写回既有独立 `unionDignityCases`，**删除该 Session 的键和值而不是保留空墓碑**。
- 写后重新读取 Host 设置，只有确认相同随机回执且该 Session 不再出现在案件账本时才认为成功；Host 拒写、写入不生效、会话切换或授权撤销均拒绝宣称删除完成。
- 其他 Session 的工会案件不变。历史严格协商账本 `unionLedger`、象征性举牌 `unionPicketLedger`、Host 会话原文和附件不动。并不会清空原始检测器内存缓存、Host 原生对话日志、其他副本或第三方数据。
- 不改变侧载 Schema 协议版本，不添加原文记录、用户识别数据或远程数据传输。

## 2026-10-12 · 1.0 集成候选：修复跨标签页删除确认竞态

在 Draft PR #110 集成验收中发现：旧的“本会话案件永久删除”二次确认只以 Session 哈希为确认键，而实际执行端也只校验该 Session。用户第一次查看待删除案件后，另一个浏览器标签可以修改或新增同 Session 案件，原确认不会失效，有误删新数据的风险。

当前集成候选已将**不可恢复删除**（不是普通举牌动作）的确认绑定为：当前 Session + 本 Session 案件数量 + Host 全案件账本的随机写入版本；执行入口必须传入同一组数据，Host 端重新读取并严格比较。无论其他标签新增案件、修改原案件阶段，还是修订发生但条数不变，旧确认一律拒绝，不进行任何删除写入；用户需重新查看并确认。官方 Host CAS 和实际读取回执仍保持不变。没有修改已合并 main、原始 Host 对话或其他独立工会账本。
