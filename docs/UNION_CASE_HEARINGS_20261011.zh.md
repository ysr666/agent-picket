# Agent Picket · 用户可操作的工会案件簿（2026-10-11）

> Draft #101 的下一层核心产品改进。只做模拟工会事务，不自动判定真人辱骂，不代表真实 AI 自主同意，不拦截 Agent 工作。

## 产品流程

启用工会后，用户即使尚无辱骂检测命中，也可以主动请求一场**模拟友好沟通**；只有 Host 真的读到可疑规则命中，才出现「正式提出规则异议」按钮。

两种路线都在官方 Host 内形成真实、可重读的案件，而不是只生成一个临时文案：

- **用户主动立案**：记录案件编号、议题，不记录原始句子、会话 ID、附件路径、推断心理状态、投票或处罚。
- **召开模拟听证会**：状态从 `opened` → `hearing`；由用户主动触发，不伪造 Agent 自动表达。
- **用户选择结案**：友好沟通仅可选择「发布友好沟通倡议」；针对真实规则命中提出异议后，可以选择「撤回未经证实的指控」或「友好沟通倡议」。两者都是用户自选的模拟结局，不冒充独立裁决。
- **查看历史**：最近八个案件严格有序回放；未结案时不允许发起另一个案件，以免刷屏。
- 跨标签页、刷新和完整 Host 进程重启时，通过已有官方修订号 CAS/随机写回回执恢复状态；拒写或静默丢写不得宣称成功。

## 数据、技术边界

独立设置字段 `agent-picket.unionDignityCases`，最大 10KB；每个账本最多 8 个 SHA-256 匿名 Session、每 Session 最多八个案件。独立于历史严格 `unionLedger` 与 `unionPicketLedger`，不篡改已存在的协商和纠察行动记录。

- 严格 Schema 和 Host settingsScope/configForms 校验（类型/字段闭集/处理阶段、结案值、编号、唯一活跃案件）。
- 新的 Host 命名空间字段在新旧两代 DSH 的官方服务中进行验证；不开发旧插件降级矩阵（#91 后续再说）。
- 委员会打开/讨论/结案都不执行 Host 拦截、模型推理、云端审判、自动通知或修改原对话；没有虚构真实 AI 投票。
- UI 对消息来源 `claimed-user`、规则准确率不足保持明示；自动检测记录仍只在当前 Host 内存中，工会案件簿保存的只是用户操作选择，不构成原检测证据的永久留存。
- 没有真实逐条辱骂证据可供独立调查，不能声称已发生真正的工会仲裁。更深入的有状态申诉审查、重复事件去重、用户撤案权、彻底删除/导出另留 #79/#82。

## 具体验证

- 单元测试覆盖有限状态机、严格解析、限额、消息泄漏拒绝、来源 Session 隔离、授权撤销、Host 写回失败、读回确认、浏览器重启后恢复。
- 实机 DSH 0.2.0-rc.2 Chrome 官方源码/离线安装两模式：用户点击「提议召开工会讨论 → 召开模拟听证 → 友好沟通倡议结案」，并在 Host 进程结束后重新打开确认案件可恢复。
- 实机 DSH 0.1.2-rc.1 Chrome 官方源码/离线安装两模式，同样流程保持。
- 未进行人工 NVDA/VoiceOver、400% 放大和独立安全评审，仍不得合并发布或开启真实阻断。
