# Agent Picket · 用户撤回未结案案件与本会话案件 JSON 导出（2026-10-11）

> Draft #106 · 对 Issue #79、#82 的可交付增量，不是完整用户数据导出/擦除。

## 具体产品体验

工会当前会话如果存在 **opened 或 hearing** 的尚未结案案件，用户可以点击「撤回未结案案件……」→「确认撤回并移除此案件」，直接移除该案件。**不强迫召开模拟听证，也不伪造裁决、AI 意愿或友好倡议。**第一击只展示确认警告，不调用 Host；第二击发起官方 Host 的受控设置写入。

此前已由用户主动结案的案件不可撤回；可以使用另外已有的两步「删除当前会话案件」清理整个会话的案件历史。撤回只是**从档案中移除**未结案记录，不另保留“撤回”历史事实；因为旧版 strict Schema 并无中立 `withdrawn` outcome，本轮不引入破坏旧版读取的字段或枚举。移除最新案件后，由于既有 schema 只用保存中的最大 ID 推算后续序号，新的立案编号可能重用，不能把该编号当成跨删除、跨时间的唯一外部事件 ID。

新增「导出本会话案件历史（JSON）」按钮，浏览器本地直接生成 `agent-picket-committee-cases.json` 下载，不上传到云端或中转服务。导出 schema 只包括 `format, schemaVersion, cases[{id,kind,stage,outcome}]`，**不包括 Host 设置、原始消息、探测原文、原会话 ID、SHA-256 Session 键、文件内容、时间戳、随机 CAS 写入回执**。

## 不可越界的 Host 条件

- 必须明确授予劳动权益模式许可，且官方 DSH Host settingsScope 实际可写。未授权、Host 不可用或 settings malformation 下都不能修改或导出。
- 触发撤回的 UI 绑定用户确认时的准确 SHA-256 会话键；实际被执行时在官方 Host 写入队列**再次验证当前 Session 键**，防止异步导航误操作另一个会话。
- 状态机只能对非闭合的已存在案件执行 `retract`。不变更已结案的案件、不重写工时/纠察/旧协议账本。
- 新设置值通过官方 Host 修订号 CAS 提交，并以唯一 128-bit 写回回执及 readback 精确比对确认。Host 拒写或静默丢写必须报错、保留旧状态。
- 如果本会话所有案件均被撤回，移除整个本会话的匿名键，避免空墓碑；其他会话和此前已结案的案件保留。

## 测试说明

- 独立状态机及 Host 测试覆盖：未听证直接撤回、已开会后撤回、已结案不可撤回、会话键不匹配、Host 拒写/静默失败、匿名键去墓碑、其他案件保留、导出严格无原文/键/令牌。
- 官方 DSH 0.2 Chrome 源码与离线安装：在真实同一会话的自动检测 → 真实 UI 异议立案 → 模拟听证结案后，下载第一份真实 JSON；另外主动发起第二项友好沟通议题，不召开听证、两次点击撤回；官方 settings/describe 读取同会话结果只剩第一项已结案案件；然后进行既有全会话双重确认删除。
- 不在 npm 包发布此工程取证文档；不改变 250KB 包体积门禁。无任何真实任务阻断。
